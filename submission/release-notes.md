# Release notes

## 1.4.1

- 将接近容量上限的 `SKILL.md` 重构为薄入口，只保留最高原则、任务卡、一级加载路由、统一执行流程、正文/状态/QA 隔离、机械审计与交付边界。
- 新增 `core-contracts.md` 作为黄金前三章、核心硬锁及旧版重复 MANDATORY 合同的单一人类可读真源；迁移不改变既有规则编号、阈值、触发条件、回滚范围或累积关系。
- 新增影子规则注册表与独立校验器，检查规则身份、来源标题、路由、相对路径和机械/语义可验证边界；注册表不复制完整规则正文，审计脚本暂不依赖注册表。
- 将合同测试从“规则全文必须位于入口”解耦为“入口直接路由 + 规范来源保留原子语义”，并继续保留正文污染、净字数和自然语境防误伤门禁。
- 本次为语义保持型架构重构；不增加、删除或放宽创作规则，不改变现有 CLI、审计 JSON 语义、逐章 2000–3200 净正文窗口或正文/状态/QA 三分离。

## 1.4.0

- 在既有三十项节奏锁上累加规则 31–60，扩展长篇续写中的逐句执行、视角边界、角色动作辨识、物件状态、章内强弱节拍与对白动作穿插等约束。
- 规则 31–60 与前 30 项及 v1/v2、01–10、九项留存、连续性和去模板化合同并列生效；不替换、不删减、不放宽任何既有规则。
- 新增规则的名称、公式、触发账、执行报告和修订说明继续只写独立 QA 侧车，不得进入读者正文或补足净正文长度。
- 机械审计只验证其已覆盖的文件结构、正文纯净、篇幅和显式状态约束；视角忠实、动作差异、节奏语义、人物动机、文学质量与市场表现仍须引用正文证据审阅。
- 所有示例仅用于理解可复用规则，示例专名、项目路径和个别剧情不得进入通用路由、模板或门禁。

## 1.3.0

- 在既有二十项节奏锁上累加规则 21–30，覆盖同段名词锚定、224 信息预算、重大伏笔回响、前十章状态结算、未知物品边界、主角每章变化、底层规则一致、同类描写去重、目标字数交集与独立 QA 执行报告。
- 新增可选 `--target-effective` 机械门禁：目标正负 20% 窗口与绝对逐章窗口取交集；未设置目标时继续使用默认 2000–3200，交集为空时按配置错误阻断。
- 三十项与 v1/v2、01–10、九项留存、连续性和去模板化合同并列累积；规则示例不进入通用门禁，事后补句不得冒充前置铺垫。
- 加固读者正文防火墙：规则 21–30 名称、公式、执行报告、拆分与修订控制文字及其混淆变体不得进入正文或补足净字数。
- 执行报告只写独立 QA 侧车；机械通过仍不证明文学质量、真实留存、付费表现或商业成功。

- 加固正文防火墙：二十项规则名、公式、IF/THEN、自检报告、重写标记及其 Markdown、HTML、Unicode 变形不得进入正文或参与字数。
- 扩展章卡与故事圣经的滚动证据账；机械审计仍不冒充节奏语义、文学质量、读者留存或商业结果证明。
