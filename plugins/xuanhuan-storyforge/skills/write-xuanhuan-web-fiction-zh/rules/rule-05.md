# Report 05 规则蒸馏

## 报告主题
百万字连载的外置记忆系统：模型没有「百万字记忆」功能，正确目标不是把 100 万字塞进 prompt，而是给写作 Agent 做一套外置记忆+按章取用——窗口=工作记忆（一次写一章够用）、文件/库=长期记忆、写前检索+写后回写=记忆功能；记忆在文件里活着，不在聊天里活着。

## 硬规则
- R05-01 正确目标不是把 100 万字塞进 prompt，而是给写作 Agent 做一套外置记忆+按章取用：窗口=工作记忆（一次写一章够用），文件/库=长期记忆（百万字级），写前检索+写后回写=记忆功能。
- R05-02 就算真有 100 万 token 窗口（约 70-80 万汉字），也不该整本扔进去：中间会丢、指令被稀释、贵、还跨不了会话。
- R05-03 先算清账：汉字 1 字≈1.3-1.8 token；番茄 1 章 2500 字≈4k；100 章约 25 万字≈35-45 万；400 章百万字网文≈140-180 万 token；一次写一章真正需要「当场看见」的通常 8k-20k token；「百万 token 记忆」=磁盘上能索引百万字，不是窗口里躺着百万 token。
- R05-04 四层记忆（只做这四层就够日更）：L0 热状态永远进 prompt（2-4k，现在桌上有什么）；L1 设定圣经写前按需进（2-6k，不变的世界/金手指规则）；L2 检索片段写前按实体召回（3-8k，旧章里相关的原文）；L3 近章原文固定进（上 1-3 章，文风和接钩）；禁止把 L2 变成「全文」；禁止不更新 L0 就写下一章。
- R05-05 记忆文件对应表：novel_state.md=进度、谁死了、桌上标的（热状态）；cast.md=人设、伤、立场、口头禅（人设锁）；debt_ledger.md=谁欠谁、原句、讨债票（虐点硬冲突）；hook_chain.md=主问、指纹物、环、下章第 1 句（钩子链）；foreshadow.md=齿点头回收状态（埋伏表）；golden_finger.md=L0-L5、已亮、代价（隐藏层）；rhythm.md=上三章爽点类型、不应期（节奏合同）；story_index=章节摘要+实体（RAG）。
- R05-06 写一章的标准流水 6 步：1. 读热状态（必读，短）；2. 根据本章出场实体检索（旧章片段+设定条目）；3. 组装「本章上下文包」（有上限）；4. 写正文；5. 强制记忆回写（不写完这一步，禁止开下一章）；6. 一致性门禁（人名、伤势、婚书、灰行、钩接没接住）；第 5 步不做，模型再聪明也会在第 30 章把退婚女写来复合。
- R05-07 热状态 novel_state.md 建议压在 1500 字内，每章覆盖写，不要追加成长文；必含字段：书/当前章/图卷/桌上标的/主问句/指纹物及位置/金手指（已亮层/灰行/本章禁用层）/欠债人升级路径（当前指到谁）/钩链（第几环/下章第 1 句）/上章兑现/上章钩型/近 3 章爽点类型（防复读）/存活关键角色（伤/立场/在哪）/已死已退场/禁止（复合、揭 L4、复读废物、系统说明书）/下一章必须接。
- R05-08 每章回写清单（memory_update.md）：新增变更角色；标的是否易手；钩链（解开哪一环、咬出哪一环、新的下章第 1 句）；埋伏（埋/点头/兑，改状态）；金手指有没有新齿；讨债票（新增/兑付）；近 3 章爽点队列左移；摘要（≤120 字，给索引用，不是散文）；检索关键词（人名、物、地点）。
- R05-09 本章上下文包（token 预算，写第 N 章只组这一包，总数盯 12k-20k token，指令+记忆；正文输出另算）：System 硬规则 3k（节奏/冲突/钩/金手指合同）；热状态 novel_state 2k；本章大纲+冲突卡+钩卡 1k；金手指+隐藏层规则 1k；相关角色卡（出场的人）1-2k；检索到的旧片段 Top4 3-4k（每条≤400 字）；上章全文 3k；上上章摘要 0.5k；本周梗池 0.5k。
- R05-10 检索查询必须从本章冲突卡生成，不要 embedding「写得好看的章」；检索条件：实体（陆沉、苏绾、婚书、青令、灰印）、关系（欠债、退婚、公证）、时间（只取已发生，不要未来大纲剧透进正文）；两级检索就够：文件名/实体表粗筛→摘要或向量精排 Top4；轻场景（纯赶路）可跳过检索，但热状态不能跳。
- R05-11 方案 B（Cursor/本地 Agent+文件状态，推荐）：写前只强制读 novel_plan + novel_state；用 grep/实体表拉旧章片段，禁止 read 全稿；写后改 state、index、伏笔表；门禁脚本（钩接没接、死人复活、金手指越层，失败则不准写 N+1）；这就是「Smart State」：上下文永远小，磁盘上的书可以过百万字。
- R05-12 方案 C（真 RAG）规则：正文入库按章切块 400-800 字，metadata=章号/实体/物；实体表+关系边（谁欠谁、物在谁手里）；时间有效性（婚书已撕，旧「未婚约」事实作废）；写前实体查询+语义精排；写后抽取实体变更，旧事实标记 superseded；注意小说 RAG 和百科 RAG 不同——相似度会召回「又一场退婚」的错章，必须先过滤实体和时间再算相似；讨债票、指纹物用结构化表，不要只靠向量。
- R05-13 记忆协议（可粘贴给模型）：你没有任何记忆，只相信本请求中的【热状态】【检索片段】【上章】[OCR存疑：原文「你沿有骑合迁记忆只相信本请求中的『执状太】检老片段】音】』」及下一行「小以有屿云旧几化。八旧平月不十时【弥机心】但余几议】止早1。」严重残缺，按上下文恢复为「不要用旧设定；'读者应该记得的事'如未出现在热状态/检索中，视为不存在」]；禁止编造未检索到的旧情节；没写在热状态里的「读者应该记得的事」视为不存在；写正文前先列出：本章用到的实体、从检索引用的 3 个约束（章号+原句要点）；正文后必须输出【记忆回写】覆盖：标的、钩环、下章第 1 句、埋伏状态、金手指层、讨债票、近 3 章爽点、120 字摘要、实体关键词；回写与正文冲突时，以正文为准并标注「状态已变」；禁止在正文里为了省事修改既定事实（死人、婚书、已亮层级）——要改必须先改大纲文件，本章作废重写；近 3 章爽点类型不得与热状态重复；下章第 1 句必须接上章钩的下一帧。
- R05-14 用户侧每章固定头：【热状态】（粘贴 novel_state.md）→【本章冲突卡】→【检索】（Top4 带章号）→【上章全文】→任务：写第 N 章，先约束列表，再正文，再记忆回写。
- R05-15 长窗口（有 100 万 token 时）只拿来体检和改纲，不要拿来日更；每 10 章做一次压缩：热状态+卷摘要；压缩结果写回文件；每次把全书当记忆=错误；每 10 章跑一次「压缩 Agent」：读这 10 章→更新卷摘要（≤800 字）→刷新 novel_state、伏笔表、债务账→列出未回收埋伏、未接钩、通胀（同型打脸）；压缩稿进 L0/L1，原文只留在 L2 索引；这样 400 章时热状态仍然 1500 字。
- R05-16 门禁 8 问（写完自动问，可用小模型）：上章钩的动作，本章第 1 句接住了吗？婚书/令/印现在在谁手里？和热状态一致吗？死过的人出现了吗？金手指用了未授权层吗？近 3 章爽点类型重复了吗？回写摘要是否漏了标的易手？一条失败→修正文或修状态，禁止开下一章。
- R05-17 方案 A（纯手工）：book/ 文件夹（prompt_system.md=爽文总合同；00_state/ 六卡；01_outline/vol01.md；03_chapters/c001.md；04_index/c001.json=摘要+实体）；每次对模型：1. 贴 System 2. 贴 novel_state+相关卡 3. 贴上章 4. 「写第 N 章」5. 模型必须先输出记忆回写块，你覆盖进文件，再存正文；没有数据库也叫百万字记忆：记忆在文件里，不在聊天记录里。
- R05-18 和你现有爽文系统怎么接：把前面那些卡全部当成记忆 schema，不要另造一套文学设定集；写第 N 章=读（节奏合同+热状态+钩链环 N+冲突卡+金手指允许层）→检索（指纹物、欠债人、出场角色的旧片段）→写（铺压弹债）→回写（环 N+1、讨债、埋伏点头、爽点队列）。

## 公式与结构模板
- 记忆协议硬线：禁止在同一聊天里无限续写到 200 章；每章新开请求，只带上下文包（本文件 R05 初稿漏提，同源 R21-17 保留，此处补录）。
- 四层记忆结构（L0/L1/L2/L3）与各层 token 预算（见 R05-04）。
- 上下文包 token 预算表（见 R05-09）。
- 记忆文件-爽文零件对应表（见 R05-05）。
- 常见崩修法（病→原因→修）：
  - 第 40 章人设漂：热状态太长等于没读 → 压到 1500 字，人设只加载出场者
  - 婚书忽好忽坏：没债务账，只靠向量 → 物的持有写成一行事实，写后覆盖
  - 钩接不住：下章第 1 句没写进状态 → 钩链文件强制字段
  - 召回错章：纯语义搜「打脸」 → 先过滤实体+章号范围
  - 同一聊天续 80 章：早期设定被挤出窗口 → 每章新请求+文件记忆

## 禁忌与反例
- 禁止：把 L2 变成「全文」；不更新 L0 就写下一章；不写记忆回写就开下一章；把 100 万字整本扔进窗口；embedding「写得好看的章」当检索；纯语义搜「打脸」召回错章；在正文里修改既定事实（死人、婚书、已亮层级）；用长窗口日更写章；每 10 章不做压缩；热状态追加成长文。
- 长窗口用法对照：窗口日更写章=不合适（贵、慢、中间遗忘）；塞进 50 章查矛盾=合适；每 10 章做一次压缩（热状态+卷摘要）=合适；每次把全书当记忆=错误。
