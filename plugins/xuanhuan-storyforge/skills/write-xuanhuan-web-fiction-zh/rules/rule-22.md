# Report 22 规则蒸馏

## 报告主题
给写作 Agent 做一套外置记忆+按章取用系统（四层记忆、记忆文件、写章流水、上下文包、门禁），实现百万字连载不崩设定——"记忆在文件里活着，不在聊天里活着"。
（注：本文件与 rule-21.md 的源 OCR 文本逐字节相同——combined-22.txt 与 combined-21.txt 为重复扫描件。为保证"一份输入对应一个规则文件"，本文件完整输出，内容与 rule-21.md 一致。）

## 硬规则

### 一、总纲
- R22-01 正确目标不是把 100 万字塞进 prompt，而是给写作 Agent 做一套外置记忆+按章取用。
- R22-02 窗口=工作记忆（一次写一章够用）；文件/库=长期记忆（百万字级）；写前检索+写后回写=记忆功能。
- R22-03 禁止把整本书扔进窗口：中间会丢、指令被稀释、贵、还跨不了会话；就算真有 100 万 token 窗口（约 70-80 万汉字）也不该整本扔进去。
- R22-04 「百万 token 记忆」=磁盘上能索引百万字，不是窗口里躺着百万 token。
- R22-05 一次写一章，真正需要「当场看见」的通常 8k-20k token，其余用卡片和检索。

### 二、四层记忆
- R22-06 只做四层就够日更：L0 热状态永远进 prompt（2-4k：现在桌上有什么）；L1 设定圣经写前按需进（2-6k：不变的世界/金手指规则）；L2 检索片段写前按实体召回（3-8k：旧章里相关的原文）；L3 近章原文固定进（上 1-3 章：文风和接钩）。
- R22-07 禁止把 L2 变成「全文」。禁止不更新 L0 就写下一章。
- R22-08 记忆文件与爽文零件对应：novel_state.md（进度、谁死了、桌上标的=热状态）；cast.md（人设、伤、立场、口头禅=人设锁）；debt_ledger.md（谁欠谁、原句、讨债票=虐点硬冲突）；hook_chain.md（主问、指纹物、环、下章第 1 句=钩子链）；foreshadow.md（齿点头回收状态=埋伏表）；golden_finger.md（L0-L5、已亮、代价=隐藏层）；rhythm.md（上三章爽点类型、不应期=节奏合同）；story_index（章节摘要+实体=RAG）。

### 三、写一章的标准流水
- R22-09 六步流水：①读热状态（必读，短）②根据本章出场实体检索（旧章片段+设定条目）③组装「本章上下文包」（有上限）④写正文⑤强制记忆回写（不写完这一步，禁止开下一章）⑥一致性门禁（人名、伤势、婚书、灰行、钩接没接住）。
- R22-10 第 5 步不做，模型再聪明也会在第 30 章把退婚女写来复合。
- R22-11 热状态模板（novel_state.md 建议压在 1500 字内，每章覆盖写，不要追加成长文）必填字段：书/当前章/图卷/桌上标的/主问句/指纹物及位置/金手指（已亮层/灰行/本章禁用层）/欠债人升级路径（当前指到谁）/钩链（第几环/下章第 1 句）/上章兑现/上章钩型/近 3 章爽点类型（防复读）/存活关键角色（伤/立场/在哪）/已死已退场/禁止（复合、揭 L4、复读废物、系统说明书）/下一章必须接。
- R22-12 每章回写清单（memory_update.md）：新增变更角色/标的是否易手/钩链（解开哪一环、咬出哪一环、新的下章第 1 句）/埋伏（埋/点头/兑，改状态）/金手指（有没有新齿）/讨债票（新增/兑付）/近 3 章爽点队列左移/摘要（≤120 字，给索引用，不是散文）/检索关键词（人名、物、地点）。

### 四、本章上下文包（token 预算 12k-20k）
- R22-13 写第 N 章只组这一包，总数盯 12k-20k token（指令+记忆，正文输出另算）：System 硬规则 3k（节奏/冲突/钩/金手指合同）；热状态 novel_state 2k；本章大纲+冲突卡+钩卡 1k；金手指+隐藏层规则 1k；相关角色卡（出场的人）1-2k；检索到的旧片段 Top4 3-4k（每条 ≤400 字）；上章全文 3k；上上章摘要 0.5k；本周梗池 0.5k。
- R22-14 检索查询从本章冲突卡生成，禁止 embedding「写得好看的章」；检索维度：实体（陆沉、苏绾、婚书、青令、灰印）、关系（欠债、退婚、公证）、时间（只取已发生，禁止未来大纲剧透进正文）。
- R22-15 两级检索就够：文件名/实体表粗筛→摘要或向量精排 Top4。轻场景（纯赶路）可跳过检索，但热状态不能跳。

### 五、三种落地
- R22-16 方案A 纯手工：一个文件夹+自己改状态，适合日更 1 章、人工盯；每次对模型：①贴 System②贴 novel_state+相关卡③贴上章④「写第 N 章」⑤模型必须先输出记忆回写块，覆盖进文件，再存正文。
- R22-17 没有数据库也叫百万字记忆：记忆在文件里，不在聊天记录里。禁止在同一条聊天里无限续写到 200 章；每章新开请求，只带上下文包。
- R22-18 方案B Cursor/本地 Agent+文件状态（推荐）：写章 skill 规定——写前只强制读 novel_plan + novel_state；用 grep/实体表拉旧章片段，禁止 read 全稿；写后改 state、index、伏笔表；门禁脚本（钩接没接、死人复活、金手指越层）失败则不准写 N+1。
- R22-19 方案C 真 RAG（多人、超长、要自动回读对白）：正文入库按章切块 400-800 字（metadata=章号/实体/物）；实体表+关系边（谁欠谁、物在谁手里）；时间有效性（婚书已撕，旧「未婚约」事实作废）；写前实体查询+语义精排；写后抽取实体变更，旧事实标记 superseded。
- R22-20 小说 RAG 和百科 RAG 不同：相似度会召回「又一场退婚」的错章；必须先过滤实体和时间，再算相似；讨债票、指纹物用结构化表，禁止只靠向量。

### 六、记忆协议（给模型，可粘贴）
- R22-21 模型没有跨会话记忆，只相信本请求中的【热状态】【检索片段】；禁止编造未检索到的旧情节；没写在热状态里的「读者应该记得的事」，视为不存在。
- R22-22 写正文前先列出：本章用到的实体、从检索引用的 3 个约束（章号+原句要点）。
- R22-23 正文后必须输出【记忆回写】覆盖：标的、钩环、下章第 1 句、埋伏状态、金手指层、讨债票、近 3 章爽点、120 字摘要、实体关键词。
- R22-24 回写与正文冲突时，以正文为准并标注「状态已变」。
- R22-25 禁止在正文里为了省事修改既定事实（死人、婚书、已亮层级）；要改必须先改大纲文件，本章作废重写。
- R22-26 近 3 章爽点类型不得与热状态重复。下章第 1 句必须接上章钩的下一帧。
- R22-27 用户侧每章固定头：【热状态】（粘贴 novel_state.md）+【本章冲突卡】+【检索】（Top4 带章号）+【上章全文】；任务：写第 N 章。先约束列表，再正文，再记忆回写。

### 七、长窗口怎么用
- R22-28 100 万 token 窗口拿来体检和改纲，禁止拿来日更；塞进 50 章查矛盾=合适；窗口日更写章、每次把全书当记忆=错误。
- R22-29 每 10 章做一次压缩（压缩 Agent）：读这 10 章→更新卷摘要（≤800 字）→刷新 novel_state、伏笔表、债务账→列出未回收埋伏、未接钩、通胀（同型打脸）。
- R22-30 压缩稿进 L0/L1，原文只留在 L2 索引；这样 400 章时热状态仍然 1500 字。

### 八、门禁（记忆假的时候靠这个抓）
- R22-31 写完自动问（可用小模型）8 问：上章钩的动作，本章第 1 句接住了吗？婚书/令/印现在在谁手里？和热状态一致吗？死过的人出现了吗？金手指用了未授权层吗？近 3 章爽点类型重复了吗？回写摘要是否漏了标的易手？一条失败→修正文或修状态，禁止开下一章。
- R22-32 常见崩的修法：第 40 章人设漂→热状态压到 1500 字，人设只加载出场者；婚书忽好忽坏→物的持有写成一行事实，写后覆盖；钩接不住→下章第 1 句写进状态钩链文件强制字段；召回错章→先过滤实体+章号范围；同一聊天续 80 章→每章新请求+文件记忆。

## 公式与结构模板
- token 账目：汉字 1 字 ≈1.3-1.8 token；番茄 1 章 2500 字 ≈4k；100 章约 25 万字 ≈35-45 万；400 章百万字网文 ≈140-180 万 token。
- 上下文包预算表：System 3k / novel_state 2k / 本章大纲+冲突卡+钩卡 1k / 金手指+隐藏层规则 1k / 角色卡 1-2k / 检索 Top4 3-4k（每条 ≤400 字）/ 上章全文 3k / 上上章摘要 0.5k / 本周梗池 0.5k，合计 12k-20k。
- 目录结构模板（方案A/B）：book/ + prompt_system.md（爽文总合同）+ 00_state/（novel_state.md、hook_chain.md、foreshadow.md、golden_finger.md、debt_ledger.md、cast.md）+ 01_outline/vol01.md + 03_chapters/c001.md + 04_index/c001.json（摘要+实体）。
- 写第 N 章标准动作：读（节奏合同+热状态+钩链环 N+冲突卡+金手指允许层）→检索（指纹物、欠债人、出场角色的旧片段）→写（铺压弹债）→回写（环 N+1、讨债、埋伏点头、爽点队列）。
- 与现有爽文系统的接法：把前面那些卡（节奏/冲突/钩/金手指等）全部当成记忆 schema，禁止另造一套文学设定集。

## 禁忌与反例
- 禁止把 L2 变成「全文」；禁止不更新 L0 就写下一章。
- 禁止编造未检索到的旧情节；没写在热状态里的「读者应该记得的事」视为不存在。
- 禁止在正文里为了省事修改既定事实（死人、婚书、已亮层级）；要改必须先改大纲文件，本章作废重写。
- 禁止在同一条聊天里无限续写到 200 章；每章新开请求，只带上下文包。
- 禁止 read 全稿拉旧章片段（方案B）；用 grep/实体表。
- 禁止只靠向量管讨债票、指纹物；用结构化表。
- 禁止检索时用未来大纲剧透进正文（时间只取已发生）。
- 一句话：别追求窗口里躺着百万 token。把书拆成热状态、账本、索引，每章只带 12-20k 的工作记忆进模型，写完强制回写。记忆在文件里活着，不在聊天里活着。
