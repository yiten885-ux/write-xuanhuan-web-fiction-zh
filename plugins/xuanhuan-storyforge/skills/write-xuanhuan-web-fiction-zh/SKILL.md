# 中文玄幻网文写作

## 1. 最高原则

1. 当前用户明确指令 > 用户确认的正史 > 当前项目故事圣经 > 已确认章纲 > 通用写作建议。
2. 区分“正史、草稿事实、后续计划”。草稿中的新事实只有被用户接受后才进入正史。
3. 用户提供的书名、人物名、样稿、路径、文档和桥段，默认只是帮助理解规则的素材。除非用户明确要求为某个项目建立专属配置，否则不得把它们写入 Skill 描述、触发路由、门禁、模板、测试或通用参考。
4. 不承诺“爆款”。只能说明完成了哪些结构、语义或机械检查；真实留存、付费和市场效果需要发布后的读者数据。
5. 公式是诊断与设计工具，不是替代因果和人物选择的填空题。第 4、5 节明确标为硬锁的数字配额默认生效；其他数字只有用户明确启用后才生效。
6. 不因作者偏好擅自禁用用户允许的叙事材料。涉及牺牲、复仇、哭泣、敏感玩笑或回忆中新揭信息时，检查因果、人物尊严、语气、来源链与连续性，但不自动判禁写。
7. 读者正文与编辑控制层永久隔离：规则名、约束 ID、自检宏、PASS/FAIL、公式拆解和审计表只能存在于内部工作区或独立 QA 侧车，绝不能进入小说标题、正文段落或正文文件。
8. 未另行指定时，每章必须独立达到 2000–3000 个净正文有效字符；不得用标题、标点、Markdown、注释、代码块、审计文字或其他章节的篇幅补足。

## 4. 黄金前三章通用合同

用户要求从零创作或重点检查前三章时，执行以下七条。它们是通用规则，不与任何示例作品、角色或文件绑定。

### 4.1 第一章前 1000 个有效正文字符出现命运危机

- 第一段直接写主角正在完成的反常或高风险动作；禁用纯环境、身世、制度或历史铺垫。
- 第二段必须出现该动作的即时物理或社会结果。
- 前 1000 字内让主角原有预期彻底落空，并产生实际利益或危机；不能只是心理惊讶或气氛预告。
- 第一个爆点发生前，禁止由叙述者解释反派多坏、处境多惨或制度如何运作；爆点后通过追逐、对峙和人物反应倒逼信息。
- 执行公式：**反常动作 → 即时结果 → 倒逼信息**。

### 4.2 背景信息通过当前代价进入

- 只交代会影响眼前选择的信息。
- 用失去的钱、错过的药、破裂的关系、迫近的期限或具体后果承载设定。
- 凡与当前困境无关的历史说明，后置或删除；爆点前不得用背景说明替代事件。

### 4.3 金手指首次有效使用展示“效果、代价、边界”

- 效果：这次具体改变了什么。
- 代价：使用者当场或后续支付什么。
- 边界：对谁、在何种条件下不能用或会失败。
- 无金手指作品不强行添加，但核心能力同样要有可验证规则。

### 4.4 主角前三章至少一次主动设局

- 不是单纯被袭后反击，而是提前选择信息、场地、见证者、诱饵或后手。
- 可以先隐藏计划，行动落地后再公平揭示。
- 设局必须由主角本人作出关键选择，不能由外挂或配角代办。

### 4.5 主要压迫者用一件完整前科立威

- 写清起因、手段、结果以及此事为何能威胁主角。
- 不用“阴狠、残暴、权势滔天”等标签替代证据。
- 前科不要求升级为猎奇伤害；只需具体、可信、可追责。

### 4.6 三章内完成一次阶段胜利

- 解决一个完整的局部矛盾，并留下可见进账、关系变化、身份变化或生存改善。
- 新危机可以更大，但不能原样撤销已经落袋的胜利。
- 钩子不能冒充回报。

### 4.7 关键设定遵循“先看见，再暗示，后揭示或使用”

- 第一次先让它造成感官、环境或权力后果，再给名称；不得先用对话或旁白讲解。
- 第二次让人物反应或对话提示其重要性。
- 第三次再解释规则、用于破局或回收因果。
- 紧急生存规则可直接说明，不为藏信息牺牲可读性。

## 5. 硬冲击章程

本节是默认强制的合取合同：创作、续写和重写正文时，所有适用项都必须满足。**v1 与 v2 是并行累积合同，v2 只能新增阈值、顺序和复检，不能删除、替换或放宽 v1。**新增 06–10 与既有 01–05 同优先级并累积执行；十条总锁只汇总，不覆盖旧锁。只有用户明确覆盖或正史使某项不适用时，才可标记例外并说明依据。

### 5.1 爽点溢出：3:1 可视偿债

对每个“主角支付可量化代价后获得回报”的场景执行：

1. 用一句话写清代价，不连续渲染受苦。
2. 以一个可观察损失记为 1 个代价单位；同一场景内至少落袋 3 个彼此可区分的收益单位。至少一项属于打脸、夺宝、收人或升阶；信息、权限和关系变化只有当场可用、可见证时才计入。
3. 若代价是血、生机、失温、伤口或物品破损，让代价本身在同一场景内转化为攻击、破锁、显形、暴露或控制媒介，不能只被主角吞下。
4. 回报不得只写“以后有用”。在回报出现的同一段落，让反派出现生理性或社会性反噬，并明确其计划、控制权或颜面如何当场破产。
5. 若无法支付三份即时收益，就删除或改写本次能力使用，不以未来伏笔赊账。

执行公式：**付出 → 回报显现 → 溢出碾压**；身体代价场景再执行 **感知痛苦 → 痛苦异变 → 痛苦反杀**。

### 5.2 钩子前置：300/800 截断

**HOOK-EMO-01｜情绪钩子前置锁**在生成第一章，或主角首次展示金手指动作的段落时触发：

1. v1 基线：首次超凡动作前，用不超过 150 字同时建立感官压迫、压迫者原话或死限、主角生理性情绪反应。v2 加锁：**共情锚点值 = 感官压迫词数 × 1 + 压迫者直接台词次数 × 2 + 时间死限或生理威胁次数 × 3**；锚点值达到 6 后，才允许首次超凡动作。
2. 第一章前 150 个有效正文字符必须依次出现：至少 2 个生理感官压迫词 → 一句带引号且由压迫者本人说出的直接台词 → 一个时间死限或生存威胁；同时写出主角一项生理性情绪反应。
3. 上述三类元素齐备前，禁止出现主角金手指、灵气、功法名、修为突破或其同义超凡展示。首次超凡动作必须晚于第 3 个自然段；全文第一句不得是系统提示、功法运转或灵气流动。
4. 从每章第一个有效正文字符计，前 300 字内出现一种异常感知，并引发主角即时动作或身体反应；主角不得先站住分析。
5. 任意相邻两次信息差截断之间最多约 800 个有效正文字符。截断采用“主角知道而读者不知道”或“读者知道而主角不知道”，落在段落开头或中段，不能只依赖章末。
6. 新能力、新物品和新人物先展示效果，至少经过下一次钩子后再解释来源。每次截断给出半个结果并留下一个可复述的问题；下一截断前不得答完。

`HOOK-EMO-01` 通过条件：**三类元素按序出现；共情锚点值 ≥ 6；首次超凡动作所在自然段序号 > 3**。任一项无正文证据，重写第一章前置范围。

执行公式：**异常感知 → 即时行动 → 结果半露 → 留白逼问**。

### 5.3 角色自利：三向利益与反向记忆

对每个有名字且连续出现超过两个段落的配角，登记：

- 对主角的立场；
- 对反派或对立方的立场；
- 对自己、家族或组织的独立利益。

第三项不得与前两项完全重合；发生冲突时，配角优先维护第三项。每个关键行动同时满足“公共身份、私人欲望、当下恐惧”中的至少两项，并让其中两项尽量互相拉扯。

反派每次行动都必须是其已知信息、资源和期限下的最优解。若方案客观愚蠢，正文必须建立使其自认合理的信息差、傲慢、时间压力或错误证据。配角第二次出场必须表现上次事件留下的行为变化，禁止重置为出厂状态。

执行公式：**公共身份 + 私人欲望 + 当下恐惧 = 行动依据**。

### 5.4 反派先拆牌：三层智斗与主角能动性并存

**PLOT-MIND-02｜智斗三层套娃锁**在任何正反对峙场景时触发。计算：**智斗深度 = 明面计划数 1 + 反拆动作数 1 + 反拆副作用利用数 1 = 3**。

1. 第一层是主角主动示出的一个可被反派感知的明面 A 计划；正文须给出明确行动证据。
2. 第二层是反派针对 A 完成一个具体 B 破解动作。B 优先摧毁证据、见证者、场地、权限或资源等出牌根基；正文须明确写出 B 如何破解 A。
3. 第三层是主角真正的 C 计划。C 的触发源必须是 B 为了成立而必然支付的隐藏代价、暴露面、空窗期或副作用；不得另取无关底牌硬压过去。
4. 同一轮冲突同时威胁至少两个主角无法同时保护的对象，逼出真实取舍。A 必须局部或完全破产，但这个绝境应在 C 的风险预期内，或迫使主角主动修正 C。
5. 反派不能只靠贪婪或暴躁行动；B 必须是其已知信息、资源与期限下的合理最优解。主角不能靠临时爆发、反派放水、外挂代办、巧合救场或机械降神完成 C。
6. 前三章主动设局仍然成立：反派可以在场景开始前完成 B 的准备，但最终破局仍由主角本人选择和执行。

`PLOT-MIND-02` 通过条件：**v1 要求至少 2 处明确计划陈述、B 对 A 的拆解动作存在、层三触发源等于层二的必然副作用；v2 再要求三层齐备且智斗深度 = 3**。任一项无正文证据，重写整个交锋场景。

执行公式：**明面 A 计划 → 反派 B 反制 → A 破产 → 主角利用 B 的必然副作用执行 C 计划**。

### 5.5 世界观砸脸：物理改写与权力坍塌

1. 新设定、新势力或重要人物第一次亮相时，先写感官异常和环境物理变化，再写名称、衣着、来历或解释。
2. 每个重要新来者必须让周围环境发生一项即时、独有且可识别的改变，不能只靠台词宣布气势。
3. 更高层级力量介入时，让当前场景最强现有势力的武器、令牌、命令、身体控制或制度权限当场失效；不得只写口头认输或众人震惊。
4. 最后用一句不超过 15 个有效字符的话重新定义归属、合法性或控制权。

执行公式：**感官异常 → 环境变形 → 旧权力失灵 → 一句话重新定义局面**。

### 5.6 情感先行：先动身体，再动脑

当主角最重要的人受到直接、迫近的生命或不可逆伤害威胁时：

1. 第一反应必须是情绪驱动的扑、挡、抓、跪、抱、夺或其他过激动作，不能先分析局势或布置策略。
2. 本能动作必须造成可测量的身体或物件代价，通过出血、失温、发白、旧伤裂开、撞伤或断物呈现，不用“心里很痛”替代。
3. 主角先确认对方状态；策略和反派动机分析至少延后一段。
4. 最重的情感落点降低动作幅度，让环境声突然消失或只剩一种持续音；主角第一句台词不超过 7 个有效字符，不使用感叹号。

执行公式：**外部刺激 → 本能动作 → 身体代价 → 环境静默 → 一句短台**。

### 5.7 金手指非线性代价

**SYS-COST-03｜非线性代价锁**在主角金手指或同类核心能力的任何生效过程时触发：

计算：**代价完整性 = 显性代价 1 + 隐性抽象损耗 1 = 2**。

1. 每次生效都明确一种当场作用的显性生理或数值代价，如气血、生机、寿元、灵力、骨骼或器官状态变化；写成可观察结果。
2. v1 要求最迟在首次至第 3 次使用间建立不可逆抽象损耗，并持续更新；v2 要求每次生效都必须同时植入一种不可逆且本章无法解释的抽象异常，并从三类中选择：感知异常；金手指本体的裂纹、刻痕或颜色等物件异常；对恨、怜悯、恐惧等情感的麻木或错位。将其记入故事圣经，本卷内暂不解释，不得遗忘或无代价复原。
3. 增益必须来自代价撬动的因果反向补偿，例如反噬敌方为获得优势所承担的损耗、转移条件、暴露债务或改写交换对象；不得写成伤害数值乘系数、掉血换攻击力或同量能量翻倍。
4. 同一场景最多出现 1 次“以伤换强”的线性操作；若再次使用能力，必须改变因果对象、规则条件或解题路径。
5. 本锁与 3:1 可视偿债同时适用：非线性说明力量如何成立，3:1 说明读者当场得到多少可见回报，两者不得互相豁免。

`SYS-COST-03` 通过条件：**本次显性代价存在；本次抽象异常存在且本章未解释；代价完整性 = 2；转化逻辑不是伤害数值 × 系数；同场景线性以伤换强 ≤ 1 次**。任一项无证据，重写能力生效过程。

### 5.8 战利品延迟释放

**LOOT-DELAY-04｜战利品双池锁**在击杀反派或阶段胜利后的第一个收获段落时触发：

1. v1 资格：即时池只展示不超过 3 项，且只能选择解除当前濒死状态或接下来 3 章内立即使用的消耗品。v2 加锁：展示出的每一项都必须在本章内直接使用，用于疗伤、补充、解锁或当前破局。不得用库存清单式数字罗列。
2. 延迟池至少保留 1 项当前作用未知、无法开启或无法安全使用的具体物件。必须套用其一并按语境变形：“容器角落还有一物，触手{冰凉/滚烫/黏腻}，神识探入即被弹开，上面{刻着/画着/缠绕着}一枚{主角名}从未见过的……”；“杂物中混着一{枚/片/块}……，{主角名}刚拿起，指尖便传来{针刺/灼烧/麻痹}，仿佛有什么东西在辨认他/她。”占位符必须替换，禁止把示例姓名写入通用门禁或正文。
3. 延迟池物件在本章内不得完成鉴定、解锁或功能说明。下一次生成相关正文时，主动让它与新危机或新机缘发生可观察联系，并把回收期限写入故事圣经。
4. 即时池的 3 项上限只约束战利品物件，不限制同场景的打脸、关系、权限或境界收益；不得借“延迟”撤销三章阶段胜利的落袋回报。

`LOOT-DELAY-04` 通过条件：**即时展示项 ≤ 3 且本章全部实际使用；未知物件 ≥ 1；未知物件本章解释次数 = 0；故事圣经存在后续挂钩承诺**。任一项无证据，重写收获段落。

### 5.9 章末异常钩子

**END-HOOK-05｜章末认知错位锁**在第三章或任意阶段性卷末的最后 200 个有效正文字符时触发：

1. 禁止用主角宣言、未来计划、心理总结或“下回分解”式旁白收尾；尤其禁止以“我、老子、本座”开头的强硬宣言。
2. v1 要求以认知错位或金手指被动异变形成客观异常；v2 必须二选一：金手指对新威胁产生与预期相反且不受主角控制的异动；已死者、令牌、遗物或延迟池物件发生复苏、变异或关联。
3. 最后一句的语法主语必须是异常现象、异变物或其客观结果，不得是主角的情绪、决心、判断或口号。
4. 该异常在当前已公开设定内必须无法完整解释；本章只给可见结果，不补答案。

`END-HOOK-05` 通过条件：**末 200 字内无主角口号、计划或心理总结；存在客观被动异变或认知错位；最后一句主语为异常现象；本章未解释该异常**。任一项无证据，重写末 200 字。

### 5.10 金手指量化边界

**BOUND-QUANT-06｜金手指量化边界锁**在主角首次使用金手指，或首次展示其代价时触发：

1. 在当前章节内用一句明确数值参照建立显性代价的总量、当前余量或每次消耗单位；至少同时给出“可比较的总量基准”和“单次变化尺度”。不得只写“一线、半指、少许”等无总量参照的模糊减少。
2. 在同一场景或紧接着的对话中给出至少一条恢复路径暗示，说明可能依赖的资源、行为、资格、地点或时间条件。暗示可以不完整或来源未证实，但必须可追查并记入故事圣经。
3. 恢复暗示只针对可量化的显性代价，不得借此撤销 `SYS-COST-03` 的不可逆抽象损耗。

`BOUND-QUANT-06` 通过条件：**本章存在总量参照；本章存在单次变化尺度；本章存在恢复路径暗示**。任一项无正文证据，重写首次展示范围。

### 5.11 主角智力上限显性化

**SMART-LIMIT-07｜智谋失算锁**在主角第二次通过智谋完成翻盘后触发：

1. 在第三次智谋翻盘之前安排至少一次预判失效或设局失败；把智谋胜负按发生顺序记入故事圣经，不得把同一布局拆成多次胜利规避计数。
2. 失败必须来自反派针对主角既有习惯、情报、诱饵、路径或计划所做的具体准备，不能归因于纯运气、临时天灾或作者强行收走底牌。
3. 失败必须造成可见的局部损失、计划破产或被迫换路；若随后进入新的智谋翻盘，仍须完整执行 `PLOT-MIND-02`，不得用本条削弱三层智斗锁。
4. 严禁连续三次智谋成功而没有一次由反派针对性布置造成的失败。

`SMART-LIMIT-07` 通过条件：**累计智谋胜利 ≥ 2 时，第三胜前已有针对性失败 ≥ 1；失败原因是反派具体布置；失败造成可见状态变化**。任一项无证据，回滚至第二胜后的安排并补写失败。

### 5.12 反派层级具象化

**VILLAIN-LAYER-08｜反派层级锁**在当前压迫反派与尚未实体出场的终极反派同时存在时触发：

1. 当前压迫反派必须拥有至少一项独特、可复现、会改变主角应对方式的追踪、封锁、感知、资源控制或制度压迫手段；不得只靠境界高、武力强、带人追赶等标签立威。
2. 终极反派实体出场前至少完成两次侧面描写，且来自不同角度：可从心腹造成的后果、环境或制度遗痕、受害者反应、物件规则、资源流向中选择；单纯在对话中重复名字不计入。
3. 两级反派的手段、资源和决策权限必须可区分，并在故事圣经记录已展示证据。

`VILLAIN-LAYER-08` 通过条件：**当前反派独特手段 ≥ 1；终极反派侧面描写 ≥ 2 且角度不同**。任一项无证据，重写对应反派的亮相或铺垫段落。

### 5.13 核心事件规则预埋

**EVENT-RULE-09｜考核规则预埋锁**在主角将参与考核、竞赛或试炼，且规则尚未公开时触发：

1. 正式开始前完整交代三项基础信息：比什么具体动作；按何种时间、精度、消耗或结果判定胜负；对手已知优势是什么。
2. 第一处规则预埋至少早于正式开始 200 个有效正文字符；开场前约 200 个有效正文字符内再自然回扣至少一次，确保规则既提前存在又仍在读者工作记忆中。
3. 规则必须嵌入逃亡、准备、争执、交易、训练、复盘等正在发生的情节，通过人物目标和动作带出；不得写成脱离场景的说明书段落，也不得等开始后再由旁白补规则。

`EVENT-RULE-09` 通过条件：**事件尚未开始时三项信息已齐；第一处预埋提前 ≥ 200 字；开场前约 200 字内有回扣；说明嵌入当前情节**。任一项无证据，重写事件开场前置范围。

### 5.14 家族谜题信息延迟

**INFO-DELAY-10｜家族谜题延迟锁**在揭示主角父辈或家族过往时触发：

1. 先在故事圣经建立可编号的核心事实清单和当前已公开比例。每次揭秘只释放一个因果层，并以至少一个新的可追查疑问交换答案。
2. 同一对话或同一场景最多释放 3 个新事实点；超过时必须拆分到后续场景。
3. 前三章关于父辈死亡真相的公开量不得超过核心事实清单的 50%，且不得超过 3 个事实点；两项上限同时取更严格者。
4. 释放信息后必须改变主角当前行动、关系或风险判断，不能只为制造设定密度。

`INFO-DELAY-10` 通过条件：**单场新事实 ≤ 3；前三章核心真相公开比例 ≤ 50% 且事实点 ≤ 3；本次产生新谜题 ≥ 1**。任一项无证据，拆分揭秘并恢复未解层。

### 5.15 斗智模式与冷却

1. 任务卡必须选择“主流玄幻模式”或“智斗/权谋模式”。未指定时默认主流玄幻模式。
2. 以完整卷或地图为统计单位：主流玄幻模式规划 70%–80% 武力、升级与结果兑现，20%–30% 智斗布局；智斗/权谋模式规划 50%–90% 智斗。比例用于卷级节奏审计，不要求逐章机械凑数。
3. 每完成一次复杂三层智斗后，至少安排 3 章以武力、升级、关系兑现或战果消化为主的冷却期，再启动下一次复杂三层智斗。
4. 小反派可在非智斗场景中用单层信息差或纯武力快速解决；一旦写成智谋翻盘，仍执行 `PLOT-MIND-02`。阶段与核心反派的非纯武力交锋必须执行完整三层智斗。

### 5.16 生成闭环与强制内部自检

1. 预检 01、02、06–10；生成时执行 03–05；创作开篇或前 30000 字时同步执行九项留存硬锁；写后在内部审计侧车逐项引用正文证据。
2. 每次生成前三章正文、单章正文或一卷正文，都必须在**独立 QA 侧车**中建立 `[OUTPUT CHECK]` 逻辑记录，逐项登记 01–10 的 `PASS/FAIL｜计算值或证据位置`。01–05 仍分别登记 `v1 PASS/FAIL｜既有 v2 PASS/FAIL`，不得合并或让十条总锁替代旧锁；另行登记九项留存锁的五个逐章检查和四个跨章/设定周期检查。未触发项写 `PASS（未触发：原因）`；尚未到期的第 10 章门槛和 6 章峰值配比只能写“尚未到期，已规划”，不得写 PASS。
3. 任一 FAIL 只回滚其触发范围，重新生成对应正文并复检；最终交付前必须十项全部 PASS，所有已到期九项留存门禁也必须全部 PASS。不得声称自动重写而实际没有重新生成。
4. **渲染防火墙**：`[OUTPUT CHECK]`、约束 ID、规则名、层一/层二/层三拆解、即时池/延迟池清单、PASS/FAIL 和修订说明都不得写入读者正文。旧合同中“附上自检”的含义统一解释为“附独立 QA 文件或内部审计记录”，绝不解释为拼接在小说末尾。
5. 用户要求保存正文时，正文文件只保存标题清单、章标题和小说正文；QA 默认另存为同目录同名 `.qa.json`。用户明确要求查看逐项审计时，也要单独交付审计文件，不得把它混入正文文件。
6. 交付前必须在**最终保存版本**上运行审计脚本。只要正文纯净门禁发现一个约束 ID、`[OUTPUT CHECK]` 或审计控制词，即判定整份正文 FAIL；先移出污染内容，再重新计算长度。
7. 机械脚本不能识别必然副作用、抽象损耗、不可逆性、第四方案、爽点语义、信息重估、正面奇观、副本闭环、设定稀缺性、翻盘类型配比或章尾安全状态，须人工复核；人工复核结论同样只进入 QA 侧车。

### 5.17 逐章 2000–3000 净正文字符硬锁

1. 未收到用户另行指定的逐章窗口时，单章、前三章和批量正文一律执行 **每章独立 2000–3000 个净正文有效字符**。三章总和、平均数或其他长章不能补偿任一短章。
2. “净正文有效字符”只统计小说叙事中的汉字、其他文字字母和数字；不统计批次标题清单、H1/H2 标题、标点、空白、Markdown 标记、HTML 注释、代码块、链接地址、编辑说明、规则 ID、自检表或 QA 内容。
3. 起稿时按每章约 2200–2800 个净正文有效字符留安全余量，但人工估算不算验收。必须对最终保存文件逐章实测，并在 QA 侧车记录每章实测值。
4. 任一章少于 2000 时，必须扩写会改变选择、阻力、关系、信息或战后状态的完整叙事单元；禁止复制句子、堆环境形容、复述规则、插入自检或用无因果对白灌水。任一章超过 3000 时，删去重复解释和不改变状态的段落后复测。
5. 执行闭环：**生成纯正文 → 移除控制层污染 → 逐章净计数 → 不足则扩写因果场景 / 超限则压缩冗余 → 再计数 → 全章 PASS 后交付**。未运行最终文件审计，不得报告字数通过。
6. 聊天中展示的正文与保存文件必须来自同一份已通过版本；不得先展示短稿、再只在文件中补字，也不得把 QA 文本算入聊天或文件的正文长度。

### 5.18 前三万字九项留存硬锁

创作开篇、前三章、前十章或前 30000 字时，完整执行 [references/opening-retention-six-locks.md](references/opening-retention-six-locks.md)。九项与七条前三章合同、v1、既有 v2、01–10、正文隔离锁及逐章净字数锁并列累积，不能替换或放宽任何既有规则：

1. 第一章前 300 个含标点的读者可见正文字符内，明确目标主体、硬性时限和不可逆后果；同时保留前 150 与前 1000 字门槛。
2. 任意滚动 3 章内至少一次“第四方案”：内部先列普通人最可能的 3 个选择，主角以已铺垫的独特能力、资源、身份、关系、知识或性格选择第四项，并直接改变剧情状态。
3. 每章至少一个落袋微爽点，任意滚动 3 章至少一个主爽点；前 30000 个净正文有效字符按用户指定公式审计密度，不重复计算同一回报。
4. 每章最后 3 句同时包含动作压力与改写既有因果判断的新信息；第三章和阶段卷末还要叠加既有客观异常末句锁。
5. 任意滚动 2 章至少一次世界体系的正面用途、惊奇、美感、便利或公共价值展示；前 30000 字正面与负面用途展示比例不低于 1:3。
6. 第 3 章结束前在正文中实际完成首次主要场景转移；第 10 章结束前完成“进入环境 → 学会规则 → 经受检验 → 获得实质升级或关键线索”的首个小副本闭环。
7. 核心外挂在“做什么、怎么做、代价是什么”三项中，至少一项与常见头部同赛道能力发生根本偏移；若需真实近三年 Top100 对照，必须另行检索，未检索时只做内部相似度排除，不声称市场事实。
8. 任意滚动 6 章内，意外型翻盘与算计型翻盘数量比保持在 2:1 至 3:1 之间，且意外型占全部翻盘至少 60%；未满 6 章时规划账不得写成已通过。
9. 每章结尾不得同时处于安全区、即时生命危险已降级为远期查线索、且本章困境已经闭环三种状态；若出现安全区，最后 3 句必须让安全规则被例外条款、反派绕过或新威胁穿透。

五个逐章检查与四个跨章/设定周期检查都只写入独立 QA 侧车。示例中的书名、专名、器物、地点、交通方式、试炼与奖励不得进入通用门禁。分数和比例是内部编辑启发式，不证明真实留存或市场表现。

### 5.19 蒸馏创作技法硬规则（26 份研究报告蒸馏合同）

本节规则蒸馏自 26 份创作技法研究报告（769 条原始规则，覆盖矩阵见 [rules/RULES-INDEX.md](rules/RULES-INDEX.md)），**与 01–10、九项留存硬锁、v1/v2 并列累积**：v3 只能新增阈值、顺序和复检，不能删除、替换或放宽既有任何锁。只有用户明确覆盖或正史使某项不适用时，才可标记例外并说明依据。

#### A. 高潮八型（详见 climax-techniques.md）

1. 高潮先改桌子（标的易手），再选嘴；没易手就换八型=空钩。【C01】
2. 一章一张嘴；半揭完又灰行又天劫=咬合失败。【C02】
3. 真高潮默认 6 新债（更高层看见指纹物，断在动作）；假高潮用 3 半揭或 1 截断，少给一档。【C03/C04】
4. 反转必须 3 齿齐且最后一行改桌子；遮断整卷≤1。【C05】
5. 灰行只亮两字+使用压力，不当唯一结算，能放余波就不抢章末。【C06】
6. 钩后零解释；下章第 1 句接这一帧并给最小画面（香在燃、剑在到、人在开口）。【C07/C08】
7. 八型=章末钩的嘴巴形状；高潮章收尾是八型最严格的用法（最后 100-200 字）。优先级：2 危机最高、8 遮断最低；强嘴（1/3/4）每 2-3 章一发；过渡章用 5 或 7。【R18】

#### B. 钩链与咬合（详见 hooks-and-chains.md）

1. 钩链是钉子，单元是锤子；一单元只咬主链一到两环，高潮咬在「升档」那一环。【B01】
2. 钩的主语=钩链下一环主语=下一单元对手。【B02】
3. 指纹物整单元不换、只改状态。【B03】
4. 钩子只做一件事：让手指点下一屏；不是伏笔、不是悬念本身。【B04】
5. 钩链五环：环1谁→环2拿着什么→环3哪条规则→环4谁写规则→环5上游要物干什么；环5 不准本单元抢。【L01】

#### C. 爽点（详见 satisfaction-and-pacing.md）

1. 爽=压力积累×释放满足×反差程度；爽点是读者欲望被当场结算的那一下（桌上那件东西易手），不是「主角赢了」。
2. 男频玄幻默认 **12 种货**（唯一口径）：打脸/装逼/掉马/升级/得宝/规则反套/真香/复仇/离场/新用法/越级/解释权；8 货列表只是简化子集。
3. 每章≥1 个落袋微爽点；任意滚动 3 章≥1 个主爽点；密度与波形按 R01-R10；与 5.1 的 3:1 可视偿债叠加执行。
4. 铺压弹债最小循环：压 50-60% / 释放 20-25% / 余震+债 20-25%；禁止连续两章纯压不给。

#### D. 记忆系统（详见 memory-and-continuity.md）

1. 模型没有百万字记忆：每章新开请求，只带上下文包。【R04-01/R21-17】
2. 禁止在同一聊天里无限续写到 200 章。【R21-17】
3. 写完一章必须执行【记忆回写】覆盖文件；正文、记忆、QA 三分文件。

#### E. 口径调和（多报告冲突时的唯一口径，组装时已统一）

| 冲突项 | 唯一口径 |

## 6. 从零创作流程

1. 明确一句话承诺：谁在什么压迫下，靠什么独特行动获得何种持续满足。
2. 建立因果骨架：缺口 → 选择 → 代价 → 状态变化 → 新问题。
3. 建立最小系统：力量来源、成长接口、资源约束、能力边界、失败后果。
4. 建立人物驱动：主角欲望与底线、关系对象的独立目标、对手的行动逻辑。
5. 先写三章状态表，再写正文；每章只承担有限的新增信息。
6. 标题服务于本章独有动作、代价或反转，避免仅换名词的万能标题。
7. 完稿后做语义审计与确定性审计，再按用户要求保存同一份最终正文。

### 6.1 编辑黑匣子模式

当用户要求“直接生成”“不要解释过程”“黑匣子模式”或等价表达时：

- 内部仍完成任务卡、因果骨架、状态表和审计，但最终只交付用户要求的成品与必要验证摘要。
- 不在正文交付前展示大纲、公式、章卡或套路分析，除非用户明确要看。
- 黑匣子模式仍须完成十项内部自检，并完成所有已到期九项留存内部自检，但只把结果写入独立 QA 侧车；读者正文及正文文件禁止出现 `[OUTPUT CHECK]`、约束 ID、规则名或 PASS/FAIL。
- 不把机械通过、结构完整或套路齐备表述为“爆款”“必火”或市场验证。
- 若生成过程中出现硬性阻塞，直接说明阻塞项、已完成项和下一步，不用创作术语包装未完成状态。

### 6.2 套路层管理

使用常见网文套路时，把套路当作因果模块，而不是装饰标签。每个被采用的套路至少记录：

- 功能：它解决哪个阅读承诺或人物压力；
- 证据：前三章内读者能看见什么具体动作、物件、关系或代价；
- 限制：它不能解决什么，或使用后要付什么成本；
- 主线交叉：它怎样推动当前敌我冲突、资源变化或身份变化；
- 删除条件：删掉它后，如果因果不变，应降级或移除；
- 状态：用户锁定 / 草稿 / 候选 / 废案。

本段“套路层管理”里的固定数量、固定章位、固定热词和题材组合只在用户明确启用时生效；**第 4、5 节已经标为默认硬锁的阈值与章位不受本句豁免**。默认优先保证因果、代价、人物选择和落袋回报。

## 7. 长篇防崩

### 7.1 三层规划

- 总纲：终局问题、主角终点、世界级因果。
- 卷纲：本卷目标、对手、资源、不可逆变化、下一卷接口。
- 滚动章纲：只细化未来若干章，并在每次重大状态变化后更新。

### 7.2 状态账

每次获得都记录：

- 获得了什么、谁控制、当前状态、使用代价、首次有效使用、后续去向。

每条冲突都记录：

- 谁要什么、为什么现在行动、主角能如何主动应对、失败会改变什么、何时结算。

### 7.3 升级不是只换数字

大境界或大地图变化至少改变一种：

- 可解决的问题；
- 必须支付的代价；
- 可见的社会权限；
- 敌人的行动方式；
- 主角对旧关系的责任。

## 8. 人物与情绪底线

1. 人物通过压力下的选择立住，不靠旁白宣布性格。
2. 配角有自己的目标、拒绝权、生活和后果，不只是主角的奖励或耗材。
3. 反派的动机可以理解，但理解不等于免责；其行为仍需承担后果。
4. 情绪点必须改变人物关系、认知、目标或行动，不能只追求读者即时反应。
5. 悲伤允许停留，人物不必按性别被规定哭多久；行动节奏服从人设和情境。
6. 喜剧的对象、尺度和后果服从用户意图与作品语气。敏感对象不是自动禁区，但需要避免无意把弱势者去人格化。
7. 回忆可以揭示新的遗言、功劳或秘密，只要存在可核对的知情者、载体、时间线和前文兼容性；不得用无来源的新事实临时修补漏洞。

## 9. 续写、重写与审校

1. 先做章前状态快照：地点、时间、人物、伤势、资源、关系、公开信息、未决钩子。
2. 写出作用域锁：允许改什么，禁止改什么。
3. 局部改稿优先最小改动，不顺手重写用户未授权的段落。
4. 续写时每个新事实标记为“草稿事实”，避免自动污染正史。
5. 审校分开报告：
   - 连续性；
   - 因果与人物能动性；
   - 节奏与回报；
   - 语言候选问题；
   - 无法由文本证明的读者或市场判断。

## 10. 确定性审计

审计脚本只检查可机械识别的候选，不证明文学质量、人物弧或市场效果。
