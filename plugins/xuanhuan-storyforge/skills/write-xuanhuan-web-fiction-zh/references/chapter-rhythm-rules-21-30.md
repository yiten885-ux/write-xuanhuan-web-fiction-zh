## 1. 共同口径与冲突仲裁

1. **新旧合取**：前二十项与本文件十项同时触发时全部满足。未触发项只能写“未触发：具体原因”，未到期跨章项只能写“尚未到期：下一检查章位”，均不得提前登记 PASS。
2. **更严上限统一**：规则二十与规则二十二合取后的有效上限统一为最多四个关键新名词；旧规则文本也已同步到该口径，不得恢复为五个。
3. **更近锚定统一**：规则二十与规则二十一的有效位置统一为同一段落、本句或下一句；旧规则文本也已同步到该口径。内部“三句内扫描”只是候选发现上限，不能把正式锚定推迟到第三句或下一段。
4. **绝对窗口不被替换**：未另行指定时，每章仍独立满足 2000–3200 个净正文有效字符。规则二十九只在任务卡登记了单章目标值时增加相对窗口；最终合法窗口是两者交集。
5. **因果优先于补指标**：提醒、成长、负面异动、节拍或长度补写必须调用已经存在的物品、人物、期限、伤势、规则或选择。不得为达标临时制造随机袭击、救兵、异常、能力使用或数值损失。
6. **数值界面按项目登记**：只有故事已经确立可量化状态界面或绝对计量单位时，才在正文使用世界内数值标注。非数值题材使用其已确立的绝对参照即时结算，不强制套用“气血 100→70”等示例。
7. **正文与 QA 隔离**：世界内状态提示可以属于小说正文；规则编号、执行依据、统计过程、通过项、未通过项和修订建议永远属于 QA。两者不得混写。
8. **机械审计边界**：脚本可以验证标题、净字数、目标字数交集和控制文字污染；名词是否真正首次出现、转折是否重大、成长是否成立、伏笔是否自然、规则是否吃书等仍需按正文与状态账语义复核。

## 2. 规则二十一：名词首次出现即锚定协议（强化版）

### 触发与强制结果

1. 新出现且要求读者记住的地名、势力名、功法名、境界名、制度名或关键物品名，必须在首次出现所在段内完成锚定，并且锚定句是首次出现句本身或紧接的下一句。
2. 锚定至少采用一种可见形式：与读者已知事物比较；展示进入、得罪、使用后的后果；给出稳定且可辨认的感官特征。
3. 锚定必须连接主角当前目标、资源或风险。只写“所谓某物，就是某物”的循环释义不合格。
4. 同一章关键新专名最终上限服从规则二十二的四个。普通人名、称谓、已解释简称和无需记忆的背景名不计，但不得借此拆名规避统计。
5. 连续两个段落出现未锚定新名词，立即合并、删去或后移其中至少一个；不得等到后文补词典说明。

内部诊断：`名词记忆成本 = 锚定距离 × 陌生度`。距离只帮助定位风险，不是允许推迟锚定的豁免。

## 3. 规则二十二：信息释放密度 224 协议

1. 单章重大剧情转折或核心真相揭露最多两个；新获得并进入主角可用资源池的物品、技能或能力最多两项；关键新专名最多四个。
2. 同一因果事实的现象、解释和后果不重复计三次；同一物品的本名、俗称和编号不重复计三项。反过来，也不得把三个独立能力合称“一个礼包”规避上限。
3. 内部计算 `章节信息载荷 = 关键新专名数 × 0.3 + 重大转折数 × 1.2 + 新获物品技能能力数 × 0.8`，结果不得超过 5.0。
4. 任一分类或总载荷超限时，优先后移与本章主选择无关的单元；把对应铺垫、获得与后果整体移到下一章，不能只删解释留下无来源结果。
5. 统计只计读者本章首次获得且需要记忆的信息。已经锚定的旧名词、旧能力常规使用、同一转折的必要反应不重复占额。

## 4. 规则二十三：伏笔三章挂起提醒协议

1. 重大伏笔或特殊物品首次出现时，在伏笔账登记首现章、可感知方式、当前持有或影响对象、下一提醒章与兑现条件。
2. 若首现章记为 N，则在 N+1 与 N+3 各安排一次简短回响；也就是首现于第一章时，第二章和第四章提醒。用户原文中的“第2章/第4章”按这个相对章位解释，不绑定全书绝对章号。
3. 回响可用主角感知、带因果的短心理、物品对当前环境的被动反应或前次事件留下的外部痕迹。目标约十五至三十个读者可见字符，必须自然挂在当前动作上。
4. 全力战斗、昏迷或 POV 无法感知时，不机械插入提示；移到本章最近的合法非战斗节拍，并在 QA 记录位置。若整章无合法位置，记录因果阻塞并在下一合法场景优先补回响，不能伪造 PASS。
5. 伏笔连续三个完整章节没有回响、兑现、作废或有证据的休眠说明，判定失忆；先检查该伏笔是否仍活跃，再修订最早缺失章。

内部诊断：`伏笔记忆留存率 = 1 - 连续沉默章数 × 0.25`。该式是编辑提醒，不是实际读者数据。

## 5. 规则二十四：代价数值前十章固定标注协议

1. 任务卡先登记“数值界面：开启/关闭/自定义”及计量单位、总量或上限、标准标注格式和恢复口径。没有登记，不得临时改成系统面板文。
2. 在数值界面开启的项目中，前十章每次核心能力造成可量化代价、恢复或上限变化，都必须在发生句句末或紧接下一句即时结算。默认骨架为 `【代价：单位 旧值 → 新值】`、`【恢复：单位 旧值 → 新值】`、`【突破：单位上限 旧值 → 新值】`，项目可以登记等价的世界内格式。
3. 前十章的标注覆盖率至少 90%，且所有关键或改变选择的结算不得遗漏；每章至少出现一次当前绝对状态参照。多个同源微小扣减可以合并为同场一次结算，但必须说明合并范围。
4. 本章没有能力调用、代价、恢复或上限变化时，不得凭空使用能力或制造损失；改用一次不虚构变化的当前状态快照，或以人物核对既有刻度的世界内动作满足每章参照。
5. 非数值题材仍执行既有量化边界锁：前十章每章至少用长度、次数、裂纹、温度、失去的感官等已确立绝对参照显示当前状态；不强制显示方括号数值 UI。
6. 世界内数值或绝对刻度提示属于正文，不是 QA；规则编号、覆盖率、PASS/FAIL 和统计表不得跟随它进入正文。

内部公式：`标注覆盖率 = 已即时标注的触发次数 ÷ 可量化代价恢复触发总次数`。

## 6. 规则二十五：未知物品功能边界三章内暴露协议

1. 引入未鉴定或功能未知的关键物品时，登记首现章、已展示功能、未知部分、当前控制者和边界披露期限。
2. 若首现章记为 N，最迟在其后的第三章 N+3 结束前披露至少一项真实边界：使用代价、失控或反噬风险、明确使用条件、无效对象或冷却限制。
3. 边界必须改变主角是否使用、如何携带、向谁隐瞒或怎样防护。只写“气息危险”“似乎有代价”而不改变选择，不算披露。
4. 到 N+3 仍未披露时，下一合法场景是修复期限；回到最早可播种位置补足因果，或在已有异常依据上兑现负面后果。不得临时让物品随机伤人来补指标。
5. 到 N+5 仍只给好处且没有限制、风险或条件，判定万能工具并阻断继续扩展功能。

内部诊断：`物品可信度 = 功能展示次数 × 0.4 + 边界披露次数 × 0.6`。检查重点是收益与边界失衡，不把分数当文学质量证明。

## 7. 规则二十六：主角每章成长痕迹协议

1. 每章至少让主角在认知、能力理解、关系、心理或短期目标中的一个维度发生可观察的状态转移。
2. 章卡必须记录章首旧状态、触发事件、章末新状态和正文证据。若新状态与旧状态相同，本章不得登记成长通过。
3. 成长可以变好、变坏、变复杂或付出代价；不要求每章升级，也不把获得物品自动等同人物成长。
4. 正文用选择、称呼变化、操作差异、回避或承担后果等具体行为证明变化，禁止旁白直接总结“他成熟了”“他更坚强了”。
5. 连续两章仅重复“战斗—恢复—再战”且认知、关系、心理和目标均无位移时，回滚到最早可改变选择的事件补足人物后果。

内部公式：`成长痕迹 = 章首旧状态 + 触发事件 + 章末新状态`，且新状态不等于旧状态。

## 8. 规则二十七：世界观底层规则一致性协议

1. 在前三章或后续正史中明确确立的能力与世界底层规则，登记首次证据、适用域、限制和已知例外；后文不得因剧情方便静默改写。
2. 规则突破只允许两类：能力升级已至少提前两章在已接受正文中出现可核对的来源锚与摘录哈希；或角色支付本场不可撤销、不可连续复制的极高代价，获得一次性越界。两类都必须更新正史与状态账。
3. 新规则或新限制原则上至少提前一章播种可见后果或异常。开篇首次建立规则、以及能从既有规则直接推出的自然后果不要求虚构更早章节。
4. 缺少前置暗示时，不得在当前段落前临时补一句并声称“早有铺垫”。应修订真正的前一章并重放下游状态，或推迟新规则到完成播种之后。
5. 新限制不能只为削弱主角，新能力不能只为解当前死局；二者都要改变后续可解决问题、代价或敌方策略。

内部公式：`规则可信度 = 首次确立证据 + 明确限制 + 未来突破铺垫`。机械脚本不证明这三项的语义成立。

## 9. 规则二十八：同类描写去重协议

1. 对同一描写对象，同章重复同一形容或动作功能两次即进入语义复核；同一具体模板词同章三次、同类模板同章四次或最近三章同对象同类表达四次，必须定向改写或删除至少一处。
2. 重点候选包括但不限于表情模板、泛化动作、突变副词和无后果气氛词。候选命中只是编辑信号，不能证明文本由 AI 生成。
3. 禁止使用同义词轮换器把一个套话换成另一个套话，也不得为去重堆叠更夸张比喻。优先改为人物职业、身体状态、地形、物件和关系压力决定的具体动作或感官后果。
4. 角色口头禅、仪式复沓、线索回声或刻意平行句可在风格卡白名单保留，但要写明叙事功能和位置。
5. 去重完成后重验事实、声线、节奏和净字数；不得改出新能力、新伤势或新正史。

内部诊断：`重复风险 = 同对象同类表达在最近三章的次数 ÷ 3`。分数只用于排序候选。

## 10. 规则二十九：章节目标净字数正负百分之二十协议

1. 任务卡增加“单章目标净字数”。用户明确给出目标 T 时，相对健康区间为 `ceil(0.8T)` 至 `floor(1.2T)`；最终合法区间再与当前绝对门禁相交。
2. 默认绝对门禁是 2000–3200，因此最终下界为 `max(2000, ceil(0.8T))`，最终上界为 `min(3200, floor(1.2T))`。例如目标 3000 时最终窗口为 2400–3200，而不是 2400–3600。
3. 用户未明确目标 T 时，不启用相对门禁，只执行当前 2000–3200 绝对窗口。用户明确覆盖绝对窗口时，先在任务卡登记，再用覆盖窗口与目标窗口取交集。
4. 目标必须为正整数；交集为空时属于配置冲突，停止生成并要求调整目标或绝对窗口，不能悄悄退回默认值。
5. 低于下界时补充一个由既有因果触发、会改变选择或状态的有效节拍；不得用环境、心理、寒暄或控制文字灌水。高于上界时先按规则二十二拆分过载，再压缩重复解释和无状态变化段落。
6. 每章独立验收，其他章节不能补偿。去重、拆分或二轮修订后必须重新实测最终保存版本。

内部公式：`章节健康度 = |实际净字数 - 目标净字数| ÷ 目标净字数`；目标未启用时不计算该项。

## 11. 规则三十：生成后执行报告协议

1. 每章生成后，在独立 QA 侧车建立规则执行报告；报告不得追加到小说正文、聊天中的正文成品或正文文件，也不得参与净字数。
2. 对所有已触发规则逐项记录状态、量化或可定位正文证据；未触发与尚未到期分别写明原因和下一检查章位。禁止无证据地写“全部通过”，也不设“至少十项 PASS”之类虚假配额。
3. 报告至少包含：章节与最终正文哈希、净字数及生效窗口；通过项与证据；未通过项、问题、最早回滚位置和修订建议；修订轮次与最终复检状态。
4. 若同轮未通过项达到三项，执行二轮修正：只重写各规则实际触发范围，重放受影响状态，生成单一最终正文，再对修订版完整复检。
5. QA 不复制整段“修正后文本”来制造第二份正文；默认记录修订前后段落锚点或哈希、修改摘要和复检结果。用户明确要看修订片段时，也在正文文件之外单独展示。
6. 机械脚本未验证的语义项必须标记“语义复核”，不得把候选扫描、公式分数或模型自评写成确定事实。

内部流程：`生成流程 = 纯正文生成 → 逐项语义与机械复检 → 局部回滚修订 → 单一最终正文 → 独立 QA 报告`。

## 12. 规则二十一至三十 QA 闭环

### 章前

1. 载入最近四章滚动账、活跃伏笔、未知物品、能力数值界面、主角状态和底层规则账。
2. 登记本章新名词预算、信息 224 预算、伏笔提醒到期项、未知物品边界期限、成长目标和单章目标净字数。
3. 先解决目标窗口与绝对窗口是否有交集；配置冲突时停止正文生成。

### 生成与修订

1. 先写纯正文；规则名、公式、检查表和修订说明不进入正文。
2. 对 FAIL 从最早因果锚点局部回滚。需要真正前置铺垫时修订前章并重放状态，不能在当前章伪造“提前”。
3. 修订后重新检查三十项全部已触发或已到期规则、正文纯净、逐章净字数、目标窗口、标题和连续性。

### QA 侧车最小字段

| 章位 / 窗口 | 规则 21–30 触发状态 | 正文证据或状态来源 | 实测值 / 期限 | 未触发或未到期依据 | 最早回滚锚点 | 修订轮次 | 最终复检 |
|---|---|---|---:|---|---|---:|---|
|  |  |  |  |  |  |  |  |

跨章另维护：关键新名词与锚定句、信息 224 计数、活跃伏笔 N+1/N+3 提醒、数值结算覆盖、未知物品边界期限、主角章首章末状态、底层规则与真正前置证据、三章表达候选、目标净字数交集和二轮修订状态。

最终报告只说明已核对的证据与明确限制。结构齐全不等于文学质量、真实留存、付费表现或商业成功。
