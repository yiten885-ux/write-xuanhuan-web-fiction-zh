# 长篇状态引擎、续写与连续性

本文件用于从零连续生成多章、续写、重写、跨场景创作、时间跳跃、多视角、揭密和全局连续性审校。局部单段创作若不依赖前文，可只执行适用部分。

> 所有状态卡、规则名、字段名、ID、JSON、检查报告、`[新增设定]` 标记和 PASS/FAIL 都属于内部控制层。读者正文只保留自然叙事；用户要求查看控制工件时，另交独立状态文件或 QA 侧车。

## 1. 状态事务总流程

每章按同一事务执行：

1. 确认用户指定的正史基线、正文版本和允许改动范围。
2. 校验上一状态版本与其绑定正文；正文与账本冲突时以已接受正文为准，从正文重建账本，不修改正文迁就旧账。
3. 从最近有效关键帧向前回溯本章实际依赖，形成最小状态切片。
4. 完成章前状态卡、风险预检、章节公式和关键帧计划；这些内容不进入正文。
5. 按场景生成到草稿缓冲；每段只使用该场景允许的人物、知识、位置、物品与能力。
6. 合并全章后提取状态增量，检查事实、人物、世界、主线、视角、知情、时间、空间和因果。
7. 从最早偏离锚点局部重写；不得在后文加一句解释掩盖早先矛盾。
8. 对最终正文重新执行标题、正文纯净、逐章净字数和语言审校。
9. 保存同一最终正文，再用正文哈希提交新状态版本；新写事实保持草稿状态，只有符合正史升级条件时才进入正史。

执行骨架：**载入状态 N → 章前预检 → 场景生成 → 章后增量 → 双向审校 → 局部修订 → 提交状态 N+1**。

## 2. 权威、事实状态与冲突仲裁

### 2.1 证据优先级

1. 用户当前明确指令；
2. 用户确认或指定为续写基线的正文；
3. 当前项目故事圣经；
4. 已确认章纲；
5. 状态库的派生记录；
6. 作者工作假设；
7. 通用类型惯例。

状态库是已接受正文的索引和缓存，不是凌驾正文的第二真源。

### 2.2 事实状态

内部事实只允许以下状态：

> 候选 → 草稿 → 正史 → 已替代；候选或草稿也可进入已否决。

- 候选解释不得进入正文。
- 同一批次的后章可以使用前章已经写出的草稿事实，但必须保持草稿标识。
- 草稿升级为正史，只能依据用户接受、用户提供为既有正文，或用户明确指定某版本为续写基线。
- 用户明确改史时，新建事实并记录被替代事实与受影响依赖；禁止静默覆盖旧事实。
- 区分未知、否定、不适用和未记录；不得把“没有记录”推断为“不存在”。

每个状态变化必须记录：**旧值 + 触发事件 + 新值 + 正文来源锚点**。来源锚点至少包含章节、场景或段落定位和稳定摘录哈希；不能只依赖会随改稿漂移的行号。

### 2.3 冲突仲裁

- 发现两条同级正史互斥时，登记未解决冲突并暂停依赖该事实的续写，不替用户猜哪条是真的。
- 用户指令修改正史时，记录替代关系，从最早受影响锚点重算人物、物品、知识、时间、位置和伏笔。
- 文采发挥、爽点公式或通用惯例与状态锁冲突时，优先保住当前用户指令和正史。
- 若只影响局部句段，最小修复；若改变因果链，明确扩大重写范围，不伪装成润色。

## 3. 十项连续性锁

这些锁与既有开篇、爽点、平台、去模板化、净字数和正文纯净合同并列，不替换任何旧锁。

连续性节奏参数统一在章卡登记，禁止散落成互相冲突的隐形数字。默认值为：每章至少改变 1 个主线状态；普通章支线正文约不超过 20%；章卡设置 1 个主任务、最多 1 个副任务；无功能寒暄最多 2 轮。用户指定支线章、群像章、情感章、慢节奏章或其他结构时，可在任务卡显式覆盖这些节奏参数；事实、POV、知情、时间、空间和因果锁不可用参数覆盖。

### R1 事实锁

- 已发生事件的生死、得失、归属、结果和公开状态不得无依据改变。
- 死亡、毁坏、消耗、公开身份等不可逆结果，只有已建立的复活、修复、回溯或撤销规则及对应代价才能改变。
- 每个新事实必须有正文来源、事实状态和版本；旧事实被改写时记录替代关系。

### R2 人物锁

- 用核心欲望、恐惧、底线、语言习惯、能力上限、当前伤势和已知信息约束选择。
- 性格变化必须经过触发事件和可见过渡；不能为推动剧情临时变聪明、变笨、变狠、变软或遗忘底线。
- 人物反应按“核心欲望 + 当前恐惧 + 习惯反应 + 当下代价”推导，不用人物卡标签代替正文行动。

### R3 世界锁

- 新规则必须能从已有规则推导，或作为草稿新设定登记来源、适用范围、边界、例外和冲突检查。
- `[新增设定]` 只用于内部状态或 QA，正文自然展示设定，不出现编辑标签。
- 新设定不得在首次出现时恰好解决核心冲突；关键用途必须先有可回看的前置证据。

### R4 主线锁

- 每章至少改变一个主线状态：目标、阻力、资源、联盟、身份、位置、期限、信息或控制权。
- 默认支线篇幅不超过本章读者可见正文约 20%；用户确认的支线章、群像章或情感章可在任务卡中覆盖，但仍要写明它与主线或人物弧的接口。
- 删除某段后若目标、风险、关系、信息和状态均不变，将其压缩或删除。

### R5 因果禁区

- 禁止机械降神、无铺垫关键人物/道具/能力、巧合解决核心冲突、无因果外援和重复解释已知信息。
- “意外型翻盘”只能是主角未预知，不能是作者无因果；外力、能力异动或对手失误必须由已存在的世界状态、人物利益或压力推出。
- 本章不引入与任务无关的新人物；确需新增时，写明其不可替代功能和前置来源。

### R6 冲突仲裁锁

- 用户当前指令可以改设定，但必须显式建立替代事实并重算下游，不静默抹去正史。
- 规则冲突先冻结受影响段落，确定优先级和最早分叉点，再继续生成。
- 任何“自动通过”都必须有正文或状态证据；无法证明时保持未知或未通过。

### R7 视角锁

- 默认每个场景只有一个焦点视角；人物只能感知该位置、身体和知识范围内的内容。
- 多视角作品只在清晰的场景边界切换，并在内部章卡登记新视角；不能在同一连续段落无标记跳头。
- 全知叙事只有在项目明确选择时使用；旁白可以知道更多，但人物不能继承旁白或其他视角的知识。
- 不为制造预感让人物准确猜中其无从知道的事实；预感若是能力，必须进入世界规则并承担边界。

### R8 信息锁

- 分开记录世界事实、每个角色知道或误信的内容、读者当前获知的内容。
- 角色取得信息必须有来源事件、取得时间、传递者或载体；未发生传递就不得用于台词、判断或计划。
- 允许“未知、怀疑、相信、确知、误信”不同状态；证据变化时才转移。
- 信息延迟只控制读者何时知道，不能倒改世界事实或让角色无故失忆。

### R9 时间锁

- 每章内部状态必须有可排序的时间锚，可用绝对历法、相对时刻或“距上一事件多久”；不强迫正文每章打印日期标签。
- 记录事件开始、结束、持续时间和可并发关系；恢复、修炼、路程、制作和消息传播必须占用合理时间。
- 时间跳跃在内部状态登记跨度和期间关键变化，正文用自然过渡提示；不能用“数日后”跳过本应改变状态的后果。
- 闪回同时记录事件发生时间与叙述框架时间，并有进入和返回锚点；不得让闪回事实污染当时人物的知情范围。

### R10 空间锁

- 记录人物起点、终点、路线、移动方式、出发与抵达时间；同一时点不能无规则地出现在两地。
- 场景切换必须有动作、交通、时间、省略依据或已建立的传送规则；不强迫正文出现 `[场景]`、`[时间]` 等控制标签。
- 场景内人物、门窗、武器、尸体、光源和关键物件位置保持可追踪；移动或易手必须发生在正文中。
- 为满足换地图、追兵或章尾钩子而瞬移仍属违规；应前移出发、调整耗时或改写前章。

## 4. 章前状态卡与依赖回溯

每章只加载影响本章的状态切片：

- 基线正文版本、状态版本和上一个有效关键帧；
- 最近相关事件，不机械限制为最近三章；
- 当前时间、地点、天气、移动条件和场景入口状态；
- 允许出场人物及其位置、伤势、能力、目标、关系和知情状态；
- 当前物品持有人、数量、消耗、冷却和使用边界；
- 运行中的期限、追兵、承诺、债务、任务和未决钩子；
- 本章将调用或回收的伏笔及其最初来源；
- 一个主任务、最多一个副任务；允许新增项和明确禁止项；
- 本章场景视角、关键帧和容易违反的锁。

从当前场景涉及的人物、能力、物品、地点、期限、关系和伏笔逆向查到正文来源或有效关键帧。达到性能上限而尚未查完时，登记“回溯不完整”并阻止连续性通过；不能把固定最近章节窗口冒充完整记忆。

章前内部检查只回答：本章要改变什么、可能冲突什么、允许新增什么、哪些信息谁能知道。不要把检查表拼进正文。

## 5. 人物和剧情状态机

### 5.1 人物状态机

为主要人物记录：

- 当前身体、情绪、立场、目标和行为倾向；
- 允许的下一状态；
- 每次转移所需的触发事件、时间、代价或证据；
- 禁止的无触发跳转；
- 最近一次转移及正文锚点。

人物状态变化必须满足：**入口状态 + 触发事件 + 人物选择 → 出口状态**。状态机约束结果，不强迫人物按模板说话。

### 5.2 剧情阶段状态机

为当前卷或地图记录：

- 当前阶段目标和进入条件；
- 尚未完成的退出条件；
- 本阶段允许揭示、允许对手和允许资源；
- 下一阶段接口；
- 禁止提前发生的核心决战、身份揭露或地图结果。

只有退出条件已在正文落地，才进入下一阶段；后续计划不得倒灌成当前事实。

## 6. 章节、场景与关键帧

### 6.1 章节与场景公式

- 章节：**入口状态 → 本章目标 → 阻力 → 人物行动 → 结果与代价 → 状态增量 → 反转或钩子**。
- 场景：**场景目的 + 在场人物及欲望 + 可用知识和资源 + 阻碍 + 行动/反制 + 可见结果 + 出口状态**。
- 对话：**说话目的 + 说话者可知信息 → 台词/回避/动作 → 对方解读 → 信息或关系变化**。动作服务潜台词，不要求每句都机械配神态；无意义寒暄最多两轮。
- 冲突：**不兼容目标 → 双方资源 → 先手/反制 → 代价 → 控制权变化 → 新隐患**。
- 悬念：**当前问题 → 缺失变量 → 部分证据 → 可复述误判或疑问 → 延迟回答 → 新问题**。
- 情感：**外部刺激 → 生理反应 → 行为冲动 → 抑制或爆发 → 关系/目标反馈**。
- 伏笔：**播种事件与载体 → 合理忽略原因 → 中途回响 → 兑现条件 → 认知或状态重估**。

### 6.2 关键帧

写正文前列出通常 3–5 个必须发生的关键帧；短场景可少于 3 个，复杂章节可多于 5 个。每个关键帧记录：

- 入口时间、地点、视角和人物状态；
- 必须发生的动作、台词功能或信息变化；
- 触发条件和前置证据；
- 场景结束后改变的事实、关系、物品、知识或风险；
- 不得出现的捷径。

关键帧是内部锚点，不是要原样塞入正文的固定句子。删除或改动关键帧时，重新检查下游依赖。

## 7. 状态库与章后增量

使用三类分离文件：

1. 正文文件：只含标题和小说正文；
2. 状态文件：保存结构化状态、事件、版本和来源锚点；
3. QA 侧车：保存规则证据、冲突、候选和修订记录。

需要机器可读状态时，复制 [story-state-template.json](../assets/story-state-template.json)。不要把 QA 报告当作状态库，也不要把状态库内容当作正文素材重复粘贴。

章后至少提取这些增量：

- 新事实及状态；
- 人物身体、修为、情绪、目标、立场和关系变化；
- 物品获得、消耗、损坏、易手和冷却；
- 地点状态与人物移动；
- 每个角色新增、修正或失去的信息及其来源；
- 时间推进、并发事件与闪回；
- 伏笔播种、回响、兑现、作废和新期限；
- 主线与剧情阶段变化；
- 新设定的来源、边界、冲突检查和首次证据；
- 未解决冲突与最早回溯锚点。

每个最终章节至少提交一个章末检查点，并按规则二十六让主角在认知、能力理解、关系、心理或目标中至少一项发生有正文证据的变化；其他未变化分类可以记录空增量并绑定最终正文哈希。修改旧章时，标记其后受影响的增量和关键帧失效，从分叉点重放，禁止原地修补最新快照。

## 8. 时间、空间、知情与伏笔账

### 8.1 角色知情账

每条知识记录：事实、角色、状态、来源事件、取得时间、传递者或载体、可信度、最后修正事件。检查角色说话和行动时，只加载其当时可用的信息。

### 8.2 时间线账

每条事件记录序号、开始、结束、持续时间、前置事件、可否并发和正文来源。时间单位服从作品历法；机械验证只能检查序号唯一、字段结构和非负耗时，不能理解自由文本历法，也不能证明路程或恢复在文学上合理。

### 8.3 位置与移动账

记录人物或关键物品的起点、终点、路线、移动方式、出发、抵达、耗时和触发事件。唯一物品同一时点只能有一个有效持有人，明确共有、复制或分身规则除外。

### 8.4 伏笔账

记录伏笔的播种事件、载体、看见者、合理忽略原因、计划回响、兑现条件、实际兑现和影响。未回收不是自动错误；被主线依赖却没有来源或被无声遗忘才是连续性问题。

## 9. 分段生成、回溯与纠偏

- 先确认全章目标、场景顺序、关键帧和出口状态，再分段生成；不能让每段各自发明下一段方向。
- 长章可按约 800–1500 个读者可见字符分段，但该数值只是稳定性参数，不改变最终逐章 2000–3200 净字数合同。
- 每段生成前只重新注入相关状态切片；不要复制整本故事圣经造成冲突稀释。
- 每段结束提取临时增量，整章未通过前不提交正史状态。
- 发现偏离时，指出违反的锁、最早错误句段、必须保留状态和允许改动范围；从最早锚点重写并检查前后衔接。
- 所谓“惩罚性指令”不产生额外约束力。使用明确的修复协议：**定位冲突 → 冻结正史 → 最小重写 → 重算增量 → 复检**。
- 模型采样参数属于调用端能力。只有用户控制运行时且模型支持时，才记录实际 temperature、top_p 等；不得声称已经调整一个无法访问的参数，也不把固定数值写成跨模型真理。

## 10. 双向与对抗性审校

### 10.1 正向回放

从最近有效关键帧按事件顺序应用增量，得到章前与章末状态。每个转移必须满足前置条件、资源守恒和触发事件。

### 10.2 逆向举证

从章末每个新状态反查触发事件、旧状态、前置条件和正文来源。正向结果与逆向来源必须一致。

### 10.3 多镜头审校

分别检查：

1. 逻辑：事件因果、资源、时间和空间；
2. 人物：欲望、恐惧、语言、能力和合法状态转移；
3. 设定：新规则来源、边界、冲突和公平铺垫；
4. 视角与知情：谁看见、谁知道、谁误信、读者知道什么；
5. 普通读者：哪里突兀、重复、跳跃或只靠作者解释成立。

对抗性提问至少覆盖：

- 这个人凭什么知道？
- 这个人和物此刻为何在这里？
- 这段路、恢复、制作或传播是否有足够时间？
- 这个能力、立场或情绪为何改变？
- 这个物品最后在谁手里，是否已消耗或毁坏？
- 这个承诺、期限、债务或追兵是否被无声遗忘？
- 这次外援、巧合或异动是否有独立因果？
- 删除旁白解释后，动作与对白仍能证明状态变化吗？
- 能否找到一条旧正史反证本章？找到则阻断交付。

高风险改史、跨卷揭密或多视角交汇可用独立审校者盲审，只提供正文、状态和任务，不泄漏预期答案。多角色自检是审校视角，不得假装多人已经真实验证。

## 11. 续写、重写和揭密

### 11.1 作用域锁

局部改稿先记录必须保留、允许调整、禁止新增和用户验收点。优先最小改动；发现范围外问题只报告，除非它阻断当前修复。

### 11.2 揭密来源链

回忆可以新增遗言、功劳、秘密或身份真相，不因“新信息”自动违规。建立：

> 事实发生者 → 记录或知情者 → 保存或记忆方式 → 此前未公开原因 → 当前公开条件 → 当前接收者

直接目击时角色可以合并多个环节。仍须检查事件发生时间、叙述框架时间、视角、知情范围、前文兼容性，以及是否临时创造终局解法。

### 11.3 旧章改动

修改旧章前生成改前关键帧；修改后列出受影响事实、人物、物品、知识、时间、位置和伏笔，失效下游派生状态并重放；完成后生成新关键帧。保留旧版本与替代关系，不把改史称为连续性修复。

## 12. 验收边界

交付前确认：

- 未解决硬连续性冲突为 0；回溯未完成时不得宣称通过。
- 每个最终章有一个绑定最终正文的章末检查点。
- 每个状态变化至少有一个触发事件和一个正文来源锚点。
- 每个角色使用的信息都有当时可用的来源。
- 每个状态机转移都有触发条件；每次移动有路线或已建立的空间规则。
- 每个唯一物品同一时点最多一个有效持有人；消耗或毁坏后不能无事件复现。
- 正文、状态文件和 QA 侧车分离；控制层污染命中数为 0。
- 最终正文仍独立满足既有逐章净字数、标题、平台、爽点和语言合同。

机械验证在提供最终正文文件后，可以实算并核对正文原始字节哈希、来源段落哈希、当前关键帧绑定、JSON 字段、ID/引用、版本链、显式转移、非负移动耗时、唯一物品单持有人及硬冲突清零；未提供正文时，含已提交事件或关键帧的状态必须失败。它不证明数量守恒、自由文本时间先后、人物动机、距离合理、情绪过渡、伏笔公平或文学质量。语义结论必须引用正文证据，不能用机械 PASS 冒充。
