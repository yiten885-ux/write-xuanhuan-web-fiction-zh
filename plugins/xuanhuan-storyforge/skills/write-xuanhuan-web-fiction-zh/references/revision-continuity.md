# 续写、重写与连续性

仅在处理既有正文时读取。

## 1. 证据优先级

1. 用户当前明确指令；
2. 用户确认的正文正史；
3. 当前项目故事圣经；
4. 已确认章纲；
5. 作者工作假设；
6. 通用类型惯例。

不得用后一级覆盖前一级。

## 2. 章前状态快照

续写或重写前记录：

- 时间、地点、天气和移动条件；
- 在场与离场人物；
- 身体、修为、装备和资源状态；
- 关系、承诺、债务和知情范围；
- 已发生的获得、损失和公开后果；
- 正在运行的期限、追兵和钩子；
- 本次允许改动与禁止改动。

## 3. 事实分层

- 正史：用户已接受或正文已明确建立。
- 草稿事实：本次新写、尚未确认。
- 后续计划：未来可能发生，不得倒灌成当前事实。
- 候选解释：用于分析，不进入正文。

新事实必须能指出来源。无法确认时，保留歧义或明确询问，不凭空补齐。

## 4. 作用域锁

局部改稿先写：

- 必须保留的句段、事件、人物和语气；
- 允许调整的顺序、措辞和信息位置；
- 禁止新增的事实、角色和世界概念；
- 用户指定的验收点。

优先最小改动。发现范围外问题时报告，不顺手改写。

## 5. 连续性检查

逐项核对：

- 时间是否足够；
- 地理移动是否可行；
- 伤势、消耗和恢复是否连续；
- 道具与资源是否在正确持有人手中；
- 能力规则是否前后一致；
- 人物是否只使用自己知道的信息；
- 关系变化是否有对应事件；
- 已落袋结果是否被无理由撤销。

## 6. 回忆与揭密

新增遗言、功劳、秘密或身份真相时，建立来源链：

> 事实发生者 → 记录或知情者 → 保存方式 → 公开时机 → 当前接收者

然后检查：

- 前文为何没有暴露；
- 当前为何能够暴露；
- 是否与视角和时间线兼容；
- 是否改变解释而不是改写已经发生的事件；
- 是否为高潮临时制造解法。

## 7. 改稿验收

输出分为：

- 已修正；
- 保留未动；
- 新增草稿事实；
- 仍有冲突；
- 需要用户确认。

机械扫描只能发现候选；最终连续性结论必须回到正文证据。
