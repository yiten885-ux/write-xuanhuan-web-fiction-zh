## 适用范围（什么时候读这份文档）

- 必须在写第 N 章前、组装「本章上下文包」前、执行【记忆回写】前、跑门禁前读这份文档；搭建写作流水线（五张状态空卡、写一章消息壳）时也必须读。
- 必须记住前提：模型没有跨会话记忆，没有「百万字记忆」功能；正确目标不是把 100 万字塞进 prompt，而是给写作 Agent 做一套外置记忆+按章取用（R05-01/R21-01）。
- 必须按此分工：窗口=工作记忆（一次写一章够用）；文件/库=长期记忆（百万字级）；写前检索+写后回写=记忆功能（R05-01/R21-02）。
- 必须理解：「百万 token 记忆」=磁盘上能索引百万字，不是窗口里躺着百万 token（R21-04）。
- 必须把记忆放在文件里，禁止把记忆放在聊天记录里：「记忆在文件里活着，不在聊天里活着」（R05-17/R21-17）。
- 必须记住流水线一句话：System 管嘴，00_state 管记得住，消息壳管这一章看见什么（R04-08）。

## 四层记忆架构（各层存什么 / 何时读写 / token 预算）

- 必须只做四层就够日更（R05-04/R21-06）：
  - **L0 热状态**：永远进 prompt，预算 2-4k token（现在桌上有什么）。
  - **L1 设定圣经**：写前按需进，预算 2-6k token（不变的世界/金手指规则）。
  - **L2 检索片段**：写前按实体召回，预算 3-8k token（旧章里相关的原文）。
  - **L3 近章原文**：固定进（上 1-3 章，文风和接钩）。
- 必须禁止：把 L2 变成「全文」；不更新 L0 就写下一章（R05-04/R21-07）。
- 必须按记忆文件对应表读写（R05-05/R21-08）：
  | 文件 | 存什么 | 对应爽文零件 |
  |---|---|---|
  | novel_state.md | 进度、谁死了、桌上标的 | 热状态 |
  | cast.md | 人设、伤、立场、口头禅 | 人设锁 |
  | debt_ledger.md | 谁欠谁、原句、讨债票 | 虐点硬冲突 |
  | hook_chain.md | 主问、指纹物、环、下章第 1 句 | 钩子链 |
  | foreshadow.md | 齿点头回收状态 | 埋伏表 |
  | golden_finger.md | L0-L5、已亮、代价 | 隐藏层 |
  | rhythm.md | 上三章爽点类型、不应期 | 节奏合同 |
  | story_index | 章节摘要+实体 | RAG |
- 方案 A（纯手工，R05-17/R21-16）：必须用 book/ 文件夹：prompt_system.md（爽文总合同）；00_state/ 六卡（novel_state.md、hook_chain.md、foreshadow.md、golden_finger.md、debt_ledger.md、cast.md）；01_outline/vol01.md；03_chapters/c001.md；04_index/c001.json（摘要+实体）。每次对模型只能：①贴 System ②贴 novel_state+相关卡 ③贴上章 ④「写第 N 章」⑤模型必须先输出记忆回写块，你覆盖进文件，再存正文。没有数据库也叫百万字记忆：记忆在文件里，不在聊天记录里（R21-17）。
- 方案 B（Cursor/本地 Agent+文件状态，推荐，R05-11/R21-18）：写章 skill 必须规定——写前只强制读 novel_plan + novel_state；用 grep/实体表拉旧章片段，禁止 read 全稿；写后改 state、index、伏笔表；必须跑门禁脚本（钩接没接、死人复活、金手指越层），失败则不准写 N+1。这就是「Smart State」：上下文永远小，磁盘上的书可以过百万字。
- 方案 C（真 RAG，多人、超长、要自动回读对白时用，R05-12/R21-19/R21-20）：正文入库必须按章切块 400-800 字，metadata=章号/实体/物；必须建实体表+关系边（谁欠谁、物在谁手里）；必须管时间有效性（婚书已撕，旧「未婚约」事实作废）；写前必须实体查询+语义精排；写后必须抽取实体变更，旧事实标记 superseded。必须注意小说 RAG 和百科 RAG 不同——相似度会召回「又一场退婚」的错章，必须先过滤实体和时间再算相似；讨债票、指纹物必须用结构化表，禁止只靠向量（R21-20）。
- 必须与现有爽文系统这样接（R05-18）：把前面那些卡全部当成记忆 schema，禁止另造一套文学设定集；写第 N 章=读（节奏合同+热状态+钩链环 N+冲突卡+金手指允许层）→检索（指纹物、欠债人、出场角色的旧片段）→写（铺压弹债）→回写（环 N+1、讨债、埋伏点头、爽点队列）。

## 上下文包（打包什么 / 多大 / 何时刷新）

- 必须遵守：写第 N 章只组这一包，总数盯 12k-20k token（指令+记忆；正文输出另算）（R05-09/R21-13）。
- 必须按此预算表组装：
  | 组件 | 预算 |
  |---|---|
  | System 硬规则（节奏/冲突/钩/金手指合同） | 3k |
  | 热状态 novel_state | 2k |
  | 本章大纲+冲突卡+钩卡 | 1k |
  | 金手指+隐藏层规则 | 1k |
  | 相关角色卡（出场的人） | 1-2k |
  | 检索到的旧片段 Top4（每条 ≤400 字） | 3-4k |
  | 上章全文 | 3k |
  | 上上章摘要 | 0.5k |
  | 本周梗池 | 0.5k |
  | 合计 | 12k-20k |
- 必须遵守检索规则（R05-10/R21-14/R21-15）：检索查询必须从本章冲突卡生成，禁止 embedding「写得好看的章」；检索条件三维度——实体（陆沉、苏绾、婚书、青令、灰印）、关系（欠债、退婚、公证）、时间（只取已发生，禁止未来大纲剧透进正文）；两级检索就够：文件名/实体表粗筛→摘要或向量精排 Top4；轻场景（纯赶路）可跳过检索，但热状态不能跳。
- 必须按固定头组装（R05-14/R21-27）：【热状态】（粘贴 novel_state.md）→【本章冲突卡】→【检索】（Top4 带章号）→【上章全文】→任务：写第 N 章，先约束列表，再正文，再记忆回写。
- 何时刷新：每章组装一次（写第 N 章只组这一包）；每 10 章必须做一次压缩刷新（热状态+卷摘要），压缩结果写回文件（R05-15/R21-29）。

## 记忆回写协议（写一章消息壳 / 五张状态空卡 / 回写触发条件）

- 必须每章新开一次请求，写完用【记忆回写】覆盖文件；禁止在同一条聊天里续写到第 200 章（R04-01/R21-17）。
- 五张空卡必须存在并逐章维护（R04-02）：
  - 00_state/novel_state.md：热状态，每章整份替换，≤1500 字；
  - 00_state/hook_chain.md：主链 3-5 环+暗链+本章钩卡；
  - 00_state/foreshadow.md：埋伏总表，一条一行；
  - 00_state/debt_ledger.md：物的持有+讨债票+后悔药；
  - 00_state/golden_finger.md：四件套+L0-L5+本章许可；
  - 用法说明必须放 00_state/README.md。
- 写一章消息壳（prompts/write_chapter_user_shell.md）用法必须固定（R04-03）：System=xuanhuan_system_prompt.txt；User=消息壳里「用户消息」整段，把 {} 换成五张卡+冲突卡+上章正文。
- 输出顺序必须锁死（R04-04，R05-14/R21-27 简版并存）：约束列表→章纲→正文→自检→记忆回写；简版：先约束列表，再正文，再记忆回写。
- 自检有 N：模型应重写正文，不要自己圆（R04-05）。
- 用记忆回写覆盖五张卡后，才允许写 N+1（R04-06）。
- 想直接开写第 1 章（R04-07）：退婚开局的样例已填好在 00_state（examples 目录；OCR 存疑：原文「examplesichLtuinhun filld nd」残缺，语义按上下文还原为「examples/退婚开局已填好样例」）；把各块抄进空卡、冲突卡贴进消息壳、上章填「无」，即可写 Ch1。
- 六步流水必须完整执行（R05-06/R21-09）：①读热状态（必读，短）②根据本章出场实体检索（旧章片段+设定条目）③组装「本章上下文包」（有上限）④写正文⑤强制记忆回写（不写完这一步，禁止开下一章）⑥一致性门禁（人名、伤势、婚书、灰行、钩接没接住）。第 5 步不做，模型再聪明也会在第 30 章把退婚女写来复合（R05-06/R21-10）。
- 热状态模板（R05-07/R21-11）：novel_state.md 建议压在 1500 字内，每章覆盖写，禁止追加成长文；必填字段：书/当前章/图卷/桌上标的/主问句/指纹物及位置/金手指（已亮层/灰行/本章禁用层）/欠债人升级路径（当前指到谁）/钩链（第几环/下章第 1 句）/上章兑现/上章钩型/近 3 章爽点类型（防复读）/存活关键角色（伤/立场/在哪）/已死已退场/禁止（复合、揭 L4、复读废物、系统说明书）/下一章必须接。
- 每章回写清单（memory_update.md）必须覆盖（R05-08/R21-12）：新增变更角色；标的是否易手；钩链（解开哪一环、咬出哪一环、新的下章第 1 句）；埋伏（埋/点头/兑，改状态）；金手指有没有新齿；讨债票（新增/兑付）；近 3 章爽点队列左移；摘要（≤120 字，给索引用，不是散文）；检索关键词（人名、物、地点）。
- 记忆协议（可粘贴给模型，R05-13 / R21-21 / R21-22 / R21-23 / R21-24 / R21-25 / R21-26）：模型没有任何跨会话记忆，必须只相信本请求中的【热状态】【检索片段】（R05-13 OCR 恢复版另含【上章】；OCR 存疑：原文「你沿有骑合迁记忆只相信本请求中的『执状太】检老片段】音】』」严重残缺，语义按上下文恢复）；禁止编造未检索到的旧情节；没写在热状态里的「读者应该记得的事」视为不存在；写正文前必须先列出：本章用到的实体、从检索引用的 3 个约束（章号+原句要点）；正文后必须输出【记忆回写】覆盖：标的、钩环、下章第 1 句、埋伏状态、金手指层、讨债票、近 3 章爽点、120 字摘要、实体关键词；回写与正文冲突时，必须以正文为准并标注「状态已变」；禁止在正文里为了省事修改既定事实（死人、婚书、已亮层级）——要改必须先改大纲文件，本章作废重写；近 3 章爽点类型不得与热状态重复；下章第 1 句必须接上章钩的下一帧。
- 回写触发条件：写完正文后强制回写（第 5 步，不写完禁止开下一章）；回写与正文冲突时以正文为准并标注「状态已变」；覆盖五张卡后才允许写 N+1；每 10 章压缩回写（R05-15/R21-29）。
- 长窗口只拿来体检和改纲，禁止拿来日更（R05-15/R21-28）；每 10 章必须跑一次「压缩 Agent」（R05-15/R21-29）：读这 10 章→更新卷摘要（≤800 字）→刷新 novel_state、伏笔表、债务账→列出未回收埋伏、未接钩、通胀（同型打脸）；压缩稿进 L0/L1，原文只留在 L2 索引；这样 400 章时热状态仍然 1500 字（R05-15/R21-30）。

## 门禁（什么信息禁止进正文 / 禁止进上下文）

- 必须写完自动跑门禁（可用小模型）（R05-16/R21-31）。门禁 8 问（OCR 原文共列出 6 问，忠实保留）：
  1. 上章钩的动作，本章第 1 句接住了吗？
  2. 婚书/令/印现在在谁手里？和热状态一致吗？
  3. 死过的人出现了吗？
  4. 金手指用了未授权层吗？
  5. 近 3 章爽点类型重复了吗？
  6. 回写摘要是否漏了标的易手？
  一条失败→修正文或修状态，禁止开下一章。
- 必须同时跑一致性门禁（六步流水第 6 步，R05-06/R21-09）：人名、伤势、婚书、灰行、钩接没接住。
- 禁止进正文的信息：未来的大纲（检索时间只取已发生，禁止未来大纲剧透进正文，R05-10/R21-14）；未检索到的旧情节（禁止编造，R05-13/R21-21）；既定事实的篡改（死人、婚书、已亮层级，R05-13/R21-25）。
- 禁止进上下文的信息：整本书/全文（禁止把 L2 变成「全文」、禁止整本扔进窗口，R05-04/R05-02/R21-03/R21-07）；「写得好看的章」的 embedding 检索结果（R05-10/R21-14）；纯语义搜「打脸」召回的错章（R05-12/R21-20）。
- 必须用门禁脚本（方案 B）：钩接没接、死人复活、金手指越层，失败则不准写 N+1（R05-11/R21-18）。

## 公式与结构模板（全部保留）

- token 账目（R05-03/R21）：汉字 1 字≈1.3-1.8 token；番茄 1 章 2500 字≈4k；100 章约 25 万字≈35-45 万；400 章百万字网文≈140-180 万 token；一次写一章真正需要「当场看见」的通常 8k-20k token。
- 四层记忆 token 预算（R05-04/R21-06）：L0 2-4k / L1 2-6k / L2 3-8k / L3 上 1-3 章。
- 上下文包预算表（R05-09/R21-13）：System 3k / novel_state 2k / 本章大纲+冲突卡+钩卡 1k / 金手指+隐藏层规则 1k / 角色卡 1-2k / 检索 Top4 3-4k（每条 ≤400 字）/ 上章全文 3k / 上上章摘要 0.5k / 本周梗池 0.5k，合计 12k-20k。
- 空模板文件表（R04-02）：
  | 文件 | 作用 |
  |---|---|
  | 00_state/novel_state.md | 热状态，每章整份替换，≤1500 字 |
  | 00_state/hook_chain.md | 主链 3-5 环+暗链+本章钩卡 |
  | 00_state/foreshadow.md | 埋伏总表，一条一行 |
  | 00_state/debt_ledger.md | 物的持有+讨债票+后悔药 |
  | 00_state/golden_finger.md | 四件套+L0-L5+本章许可 |
  | 00_state/README.md | 用法说明 |

- 写一章消息壳 5 步（发给模型时，R04-03/R04-04/R04-05/R04-06）：①System=xuanhuan_system_prompt.txt；②User=消息壳「用户消息」整段，把 {} 换成五张卡+冲突卡+上章正文；③输出顺序锁死：约束列表→章纲→正文→自检→记忆回写；④自检有 N：模型应重写正文，你不要自己圆；⑤用记忆回写覆盖五张卡后，才允许写 N+1。

- 方案 A 每章 5 步（R05-17/R21-16）：①贴 System ②贴 novel_state+相关卡 ③贴上章 ④「写第 N 章」⑤模型必须先输出记忆回写块，你覆盖进文件，再存正文。
- 目录结构模板（方案 A/B，R21）：book/ + prompt_system.md（爽文总合同）+ 00_state/（novel_state.md、hook_chain.md、foreshadow.md、golden_finger.md、debt_ledger.md、cast.md）+ 01_outline/vol01.md + 03_chapters/c001.md + 04_index/c001.json（摘要+实体）。

- 写第 N 章标准动作（R05-18/R21）：读（节奏合同+热状态+钩链环 N+冲突卡+金手指允许层）→检索（指纹物、欠债人、出场角色的旧片段）→写（铺压弹债）→回写（环 N+1、讨债、埋伏点头、爽点队列）。
- 常见崩修法（病→原因→修，R05/R21-32）：第 40 章人设漂→热状态太长等于没读→压到 1500 字，人设只加载出场者；婚书忽好忽坏→没债务账，只靠向量→物的持有写成一行事实，写后覆盖；钩接不住→下章第 1 句没写进状态→钩链文件强制字段；召回错章→纯语义搜「打脸」→先过滤实体+章号范围；同一聊天续 80 章→早期设定被挤出窗口→每章新请求+文件记忆。

## 禁忌与反例

- 禁止在同一条聊天里续写到第 200 章（每章新开请求，只带上下文包）（R04-01/R21-17）。
- 禁止自检出 N 时自己圆（必须让模型重写正文）（R04-05）。
- 禁止未用记忆回写覆盖五张卡就写 N+1（R04-06）。
- 禁止把 L2 变成「全文」；禁止不更新 L0 就写下一章（R05-04/R21-07）。
- 禁止不写记忆回写就开下一章（R05-06/R21-09）。
- 禁止把 100 万字整本扔进窗口（R05-02/R21-03）。
- 禁止 embedding「写得好看的章」当检索；禁止纯语义搜「打脸」召回错章（R05-10/R05-12/R21-14/R21-20）。
- 禁止在正文里修改既定事实（死人、婚书、已亮层级）；要改必须先改大纲文件，本章作废重写（R05-13/R21-25）。
- 禁止用长窗口日更写章；禁止每次把全书当记忆（R05-15/R21-28）。
- 禁止每 10 章不做压缩（R05-15/R21-29）。
- 禁止热状态追加成长文（必须每章覆盖写，压 1500 字内）（R05-07/R21-11）。
- 禁止编造未检索到的旧情节；没写在热状态里的「读者应该记得的事」视为不存在（R05-13/R21-21）。
- 禁止 read 全稿拉旧章片段（方案 B）；必须用 grep/实体表（R05-11/R21-18）。
- 禁止只靠向量管讨债票、指纹物；必须用结构化表（R05-12/R21-20）。
- 禁止检索时用未来大纲剧透进正文（时间只取已发生）（R05-10/R21-14）。
- 长窗口用法对照（R05-15/R21-28）：窗口日更写章=不合适（贵、慢、中间遗忘）；塞进 50 章查矛盾=合适；每 10 章做一次压缩（热状态+卷摘要）=合适；每次把全书当记忆=错误。
- 一句话总结（R21）：别追求窗口里躺着百万 token。把书拆成热状态、账本、索引，每章只带 12-20k 的工作记忆进模型，写完强制回写。记忆在文件里活着，不在聊天里活着。
